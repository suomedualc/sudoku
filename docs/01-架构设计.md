## 3. 各层职责与依赖方向

依赖严格单向，下层不知道上层存在：

- **core**：只依赖 Kotlin 标准库与 `kotlin.random.Random`。规则、求解、出题、冲突判定均在此，**禁止**出现 IO、时钟、UI。
- **state**：依赖 `core` 与 `state` 自身类型；`GameReducer` 是纯函数（无 `State`/`Composable`/IO），保证可单测、可确定性回放。
- **ui**：依赖 `state`（取状态、派发 Action）与 `core`（类型）。所有 Compose / Canvas 调用仅在此层。
- **entrypoints**：仅做平台装配（窗口、Activity），业务逻辑全部复用 `ui.App`。

## 4. 数据流（单向，Elm 式）

```
输入（点击 / 键盘 / 心跳校对）
   │  GameAction
   ▼
GameViewModel.dispatch(action)
   │  GameReducer.reduce(state, action, rng) → Reduction(state, message)
   ▼
新 GameState  ──► Compose 重组（读 state 重绘）
   │
   ├─ message ─────► Channel<String> 事件通道 ──► Snackbar（相同文案也逐条送达）
   ├─ GameStore ───► 存档落盘（每 10 秒节流；**设置常驻**，对局在通关 / 结算后从存档移除）
   └─ 计时 ────────► 心跳每 250ms 调 syncClock()：按**单调时钟**算真实秒数，
                     仅在整秒变化时 dispatch SyncElapsed（暂停 / 离开界面 / 最小化自动停表）
```

- **状态是单一真相**：UI 永远从 `GameState` 生成，不缓存派生结果。
- **副作用外提**：提示由 `reduce` 的返回值交给事件通道 → Snackbar；计时由心跳按**真实时间**同步（reducer 不读时钟）；存档由 `GameStore` 端口承担。
- **随机源注入**：出题用 `Random(seed)` 注入，保证可复现（固定种子→同一盘面），便于跨端对拍与测试。

## 5. 核心状态机要点

`GameState` 关键字段：`screen`（**只有 Menu / Game**；原统计页已随"首页三入口"改版移除）、`game`（题面 / 当前 / 答案 / 难度）、`selected`、
`notes[81]`、`noteMode` / `strictMode` / `showNotes` / `hintCandidates`、`undoStack/redoStack`（快照栈）、`elapsed` / `paused`、
`hintUsed` / `hintsCount`、`revealed` / `settled` / `won`。
**一次性提示不在状态里**：`reduce` 返回 `Reduction(state, message)`，由 `GameViewModel` 送进事件通道 → Snackbar。
派生属性 `interactive` 汇总"何时接受输入"：Game 屏 + 有对局 + 未暂停 + 未结算 + 未通关。
派生属性 `settings` 把 `strictMode / showNotes / noteMode / hintCandidates` 投影成 `GameSettings`，供存档使用——这四项**跨对局保留**
（`NewGame` 显式继承，`Reset` / 通关 / 重开都不清空），与"对局状态"划清界限。
纯 UI 细节（如"悬浮输入面板此刻锚在哪一格"）**不进状态**，由 `GameScreen` 的 `remember` 持有。

`GameReducer` 实现的关键语义（括号中的 A3/A4 是历史 TS 版的验收编号，保留以便对照）：

| 行为 | 说明 |
|---|---|
| 出题 | 随机化回溯生成终盘 → 按难度挖洞 → `countSolutions(puzzle, 2) == 1` 保证唯一解；贪心挖不满时**重试至达标**（最多 6 次，每两次换终盘），兜底分支连同一终盘返回，保持"题目 ⊆ 终盘" |
| 落子 | 给定格拒绝；笔记模式仅对空格生效（A3）；同数字再按 = 清除；无变化的输入不写入撤销栈 |
| 移动 | 方向键选格：沿方向逐格前进并**跳过给定格**（A4），仅在本行 / 列内环绕 |
| 冲突 | 每次落子重算 `conflictFlags`，棋盘标红 + Snackbar 提示；同时清理同行列宫的该数字候选 |
| 严格模式 | 目标数字与同行列宫冲突时拒绝落子并提示（只约束新落子，不改写已有冲突） |
| 判胜 | 方案乙：填满无冲突 **且** 与标准答案逐格一致（唯一解题目下等价，双保险且零分配） |
| 撤销/重做 | 改盘前压栈快照（盘面 + 笔记 + `hintUsed` + `hintsCount` + `revealed`），上限 300 步；重做会重新推导 `settled` |
| 提示 | 优先填当前选中空格，否则第一个空格；标记 `hintUsed` 并累加 `hintsCount` |
| 候选提示 | 切换 `hintCandidates`（不改动选中格）。绘制在 `ui` 层：**所有空格**用**半透明灰**数字画出 `Sudoku.legalMask` 的结果（整盘一次算好，`remember(game.current)` 缓存，只在盘面变化时重算）；玩家自己的笔记优先显示 |
| 悬浮输入面板 | 纯 UI 细节，不进状态机：**只列该格可填的数字**、键 48dp、尺寸按候选个数自适应；位置 / 尺寸 / 开合判据都在 `ui/components/FloatingPad.kt` 的 `FloatingPadPolicy`（纯函数 + 单测），锚点格由 `GameScreen` 的 `remember` 持有 |
| 暂停 / 计时 | 秒数由单调时钟算出（`SyncElapsed`，reducer 不读时钟）；暂停、结算、离开对局界面（`screen != Game`）、窗口最小化都会停表 |

## 6. 与 TypeScript 版的关系

`core/Sudoku.kt` 是 TS 版 `packages/core` 的**算法等价移植**（位掩码 + MRV、唯一解挖洞、冲突扫描、判胜方案乙），
不是逐行等价——Kotlin 版另加了 `legalMask`、`Move` 跳给定格、快照含提示计数等改动。
TS 版已整体归档至 `archive/`（`legacy/` 展开源码 + zip 包），当前仅维护 Kotlin 工程；
固定随机源使两版可用同一批种子做**行为对拍**（当前只在 Kotlin 侧做了单测）。

## 7. 已知约束

- **依赖只有 JetBrains 官方产物**（Compose / Kotlin / Skiko，另有协程与 lifecycle 由它们传递引入）；
  没有第三方 UI 组件库，因此**不存在"库与编译器强绑定"的约束**——历史上曾有一个第三方 UI 库强制
  Kotlin / CMP / 自身三者整体对齐，该依赖已移除（过程见 `docs/05` §5.8）。
- Gradle wrapper 已提交（8.12）；Kotlin 2.5 起将要求 Gradle ≥ 8.14.4，升级 Kotlin 时需同步换 wrapper。
- Android 目标启用条件（2026-10-07 复核）：`compileSdk 37` 这个硬约束**来自此前那个第三方 UI 库的 aar，已随该依赖一并移除**；
  本机现有的 android-35/36 即可用。要补的是 AGP 插件 / `androidTarget()` / `androidx.activity:activity-compose`
  依赖 / 图标资源，以及 `SafeArea.kt` 的 android actual（安全区）。
- 完整构建需具备网络（首次拉取 Compose 依赖）；本仓不含依赖缓存，但本机 Gradle 缓存已就绪，日常可 `--offline`。
- **JDK 约束**：启动 Gradle 的 `JAVA_HOME` 必须是 JDK 17–24（本项目用 21）；JDK 25 会让 Gradle 8.12 直接失败
  （报错只有一串版本号）。`composeApp/build.gradle.kts` 已用 `jvmToolchain(21)` 固定编译目标。
- **归档只读**：`archive/` 下的 TS / Rust 实现仅为历史资料，语义与当前 Kotlin 实现不保证一致，禁止作为参照实现引用。
