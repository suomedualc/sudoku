## 1. 三条铁律

1. **只有纸与墨**：纸 = `Ink.Paper`，墨 = `Ink.Black` / `Ink.Grey` / `Ink.Light`。
   **禁止任何色相**——包括"用红色标错"。层次一律靠墨的浓淡（alpha）与线条本身。
   两套主题（浅色「纸墨」`#F7F5F0` 底 / 深色「夜墨」`#121110` 底）都遵守这一条，
   墨的名字表示**层级**而非绝对色值：夜墨下"一墨"是近白色（见 §11）。
2. **手绘而非几何**：所有边框、网格、勾选、排线都用 `inkLine / inkRoundRect / inkHatch` 绘制
   （折线微弯 + 叠一遍淡墨，模拟笔触不匀）。抖动的种子是**纯函数**（由位置/文本哈希决定），
   因此重绘与重组时线条完全静止，不会"抖"。
3. **留白优先**：间距节奏比 Material 更疏（Md 16 / Lg 24 / Xl 32 / Xxl 48 dp）；
   宁可加大留白，也不加装饰与分隔块。

### 2.1 `ui/theme/Ink.kt` —— 颜色 / 字体 / 绘制原语

| 类别 | 令牌 | 值 / 说明 |
|---|---|---|
| 主题开关 | `Ink.isDark` / `Ink.setDark()` / `Ink.darkMode` 偏好 | 快照状态（不是 `CompositionLocal`——绘制层也要读，见 §11）；**唯一写入点是 `App.kt` 的主题同步** |
| 纸 | `Ink.Paper` / `Ink.PaperShade` / `Ink.PaperSheet` | 纸墨 `#F7F5F0` / `#EDE9DF` / `#FFFFFF`；夜墨 `#121110` / `#0B0A09` / `#1E1C17`。三层**由下往上逐层变亮**，两套主题方向一致 |
| 墨 | `Ink.Black` / `Ink.Grey` / `Ink.Light` / `Ink.Faint` | 纸墨 `#1B1A17` / `#4B4843` / `#6A655C` / `#8B867C`；夜墨 `#F0ECE3` / `#C9C3B8` / `#A39D93` / `#767068`。名字表示**墨的层级**，夜墨下一墨反而最亮；前三级可当正文，`Faint` **仅禁用态** |
| 遮罩 | `Ink.Scrim` | 模态遮罩：纸墨 `#000` × 16%，夜墨 × 46%。**必须单独开一个令牌**——它不能跟随 `Black`（夜墨下 `Black` 是近白色，拿它当遮罩会变成一层白光），且深底要更大浓度才有同样的"退后"效果 |
| 墨的浓淡 | `Ink.Alpha.Line / LineSoft / Hair / Wash / WashStrong / Disabled` | `0.88 / 0.42 / 0.16 / 0.07 / 0.14 / 0.26`（与主题无关，对两套都成立） |

| 绘制原语 | `inkLine` / `inkRoundRect` / `inkHatch` | 手绘直线（含虚线模式）、手绘圆角矩形、斜排线 |
| 图标 | `InkIcon` + `drawInkIcon` | 返回 / 撤销 / 重做 / 暂停 / 继续 / 重置 / 提示 / 月牙 / 太阳，**全部用 `inkLine` 与弧线自绘**（不引图标库、不用图标字体） |

### 2.3 字体来源与授权

字体**随包分发**（`composeApp/src/jvmMain/resources/fonts/`），保证跨设备 / 跨平台字形一致（`docs/07` P1-3 落地）：

| 用途 | 字体 | 授权 | 体积 |
|---|---|---|---|
| 正文 / 标题（中文 + 英文） | 霞鹜文楷 **LXGW WenKai** Regular | SIL OFL 1.1 | 24.4 MB |
| 数字（棋盘格内数字 / 笔记 / 候选、数字键盘键位、计时 / 进度 / 通关用时） | **Nunito**（变量字体，**中文回退霞鹜文楷**） | SIL OFL 1.1 | 270 KB |

**选型理由**

- 正文用霞鹜文楷：温暖手写、字面清晰，与「手写纸 · 简约油墨」同源，且是指定的主选项；
- 数字用 Nunito：圆润人文无衬线，圆笔气质与手写呼应；数字是数独的**核心信息**，
  小字号下手写体笔形发虚、6/9 易混（与 `docs/06` 图标「数字用无衬线」的结论一致）；
  Nunito 有真实字重，给定 / 填入数字可用字重分层，不再依赖手写体合成粗体；
- **只对"数字读数"用 Nunito**：棋盘格内数字 / 笔记 / 候选、数字键盘键位、**计时、进度（`done / total`）、通关用时**；
  **夹在句子里的数字仍走正文字体**（如「提示 ×2」「本局用时 02:06」）——读作「文字里的数字」。
- **数字族带中文兜底**：`FontDigits` = Nunito + 霞鹜文楷的**回退链**。计时位在暂停时显示「已暂停」，
  若数字族只有 Nunito，中文会渲染成豆腐块；带兜底后中文自动落回手写体，调用点不必按内容分叉。

**加载与回退**

- 桌面（`jvmMain/ui/theme/InkFonts.jvm.kt`）：打包字体在 jar 内不是磁盘文件，而桌面 `Font` 工厂
  （Compose Multiplatform 1.11）只剩 `Font(identity)`（系统字体名）与 `Font(file)`（磁盘文件）两个入口，
  故先把资源落到临时文件再用 `Font(file)` 装载（与旧代码「从系统字体文件加载」同一条 `FileFont` 路径）。
- 回退链：正文 = 打包霞鹜文楷 → 系统楷书（`FZYTK` / `simkai` / `STKAITI` / `Kaiti` / `NotoSerifCJK`）→ 衬线体；
  数字 = 打包 Nunito → **霞鹜文楷**（族内按码点回退）→ 无衬线体。取不到也**绝不因缺字体而崩**。
- 组合回退链要拿 `Font` 对象再传给 `FontFamily(...)`：这个版本的 `FontFamily.fonts` 是 internal，
  拿不到已建好的族去"再拼一遍"；`digitFontChain()` 暴露给测试，断言兜底没被删掉（删了中文会静默变豆腐块）。
- 授权合规：两份字体都是 **OFL 1.1**，允许随软件捆绑；打包的是**未修改原版**，保留字体名合法
  （霞鹜文楷的 OFL 声明保留「LXGW / 霞鹜」等名，若后续为移动端做子集，需按 OFL 第 3 条处理保留名）。
  授权原文随包（`fonts/OFL-LXGWWenKai.txt`、`fonts/OFL-Nunito.txt`）。

## 3. 组件规范（自绘墨线组件）

设计意图：**不引入任何第三方组件库**，骨架、控件与提示全部自绘（见 §3.2）；
所有可见控件由 `ui/components/InkWidgets.kt`（控件）与 `InkSnackbar.kt`（提示）自绘。

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `InkSurface`（私有） | 所有可点控件的交互底子 | 统一五态反馈，见下表 |
| `InkButton` | 主 / 次操作按钮（菜单项、控制条、墨框按钮） | `emphasized` = 重墨框 + 大字；`compact` = 42dp 高；`highlighted` = 首页键盘选中项 |
| `InkKey` | 数字键 / 小方块墨键 | `emphasis` 重墨 = 可填；`soft` 淡墨 = 不可填；禁用不禁用功能（见 §6） |
| `InkToggleRow` | 玩法开关 | 整行 `toggleable(role = Role.Switch)`；勾选是手绘"✓"，不依赖颜色 |
| `InkPanel` | 分组容器（替代 Card） | 白纸面 + 淡墨手绘边框；`paperAlpha < 1` 半透明纸面（悬浮面板用），`doubleStroke` 错位双描边表达"浮起"（不用阴影）；`fillWidth = false` 按内容收紧宽度（**浮动操作条**用：两个按钮撑满整宽会变成横贯棋盘的空白带，抢棋盘的注意力） |
| `InkIconButton` | 图标按钮（顶栏与浮动条） | 方形 36dp + 手绘图标，复用 `InkSurface` 的完整五态；图标只做形状，**说明走 `contentDescription`**（读屏读"撤销"，不读"一个圆圈带箭头"） |
| `FloatingInputPad` | 半透明悬浮数字面板（鼠标 / 触控笔点空格） | **只列该格当前可填的数字**（不列 1–9 全部）；尺寸按候选个数自适应（键 48dp、最多 3 列）；位置由 `FloatingPadPolicy` 计算；不接管焦点 |
| `TopDrawer` | **全部覆盖层**：难度选择 / 退出确认 / 通关结算 | 全屏墨色遮罩（16% 黑，`Ink.Alpha.Mask`）+ 顶部滑入纸片（内容限宽 560dp）；只有下缘圆角 + 顶部"抓手段"；`dismissible = false` 时点遮罩不关闭（通关用）；键盘由 `TopDrawerKeys` 模态仲裁，见 §4.2 |
| `InkTitleFrame` | 首页标题 | 双层手绘矩形 + 两侧墨点与短竖线装饰 |
| `InkDivider` | 面板内分隔 | 一条淡墨手绘线（替代分割块） |
| `InkGridSketch` | 首页底部装饰 | 9×9 手绘草图 + 几枚"随手点下的墨迹" |
| `BoardCanvas` | 棋盘 | 见 §6 |
| `InkSnackbarHost` / `InkSnackbarHostState` | 一次性提示（替代组件库的 Snackbar） | 上层纸片 + 手绘墨框 + `Ink.Type.Caption`；**不拦截点击**；保留"挂起排队"与"相同文案也算新的一条"（自增 id，单测守着）；出入场过 `motionDurationMs` |

**五态反馈（全站统一，动画时长 90ms）**

| 状态 | 视觉 |
|---|---|
| 常态 | 手绘墨框（中墨 / 重墨 / 淡墨由 `emphasis`、`soft` 决定） |
| 悬停（桌面） | 加一层极淡墨洗（`Alpha.Wash`） |
| 按压 | 墨洗加深 + 整体下移 1dp（"按下去"的手感） |
| 焦点（键盘 Tab） | 内侧再叠一圈细描框 |
| 键盘高亮（首页 ↑↓ 当前项） | 比悬停更淡的墨洗（`Alpha.Wash × 0.55`）+ 同一圈内侧细描框——复用焦点视觉，不新增语言 |
| 禁用 | **虚线框** + 淡墨字（不依赖颜色传达"不可用"） |

### 3.1 首页（`MenuScreen`）

结构对齐参考图：**标题墨框 → 竖排主菜单 → 底部棋盘草图**，但只用墨线与留白表达。

- 标题：「数独」+ 副标题「SUDOKU · 手写纸」，居中于双层墨框内，两侧各一墨点 + 短竖线。
- 菜单**仅三个入口**（硬性要求）：
  1. `开始游戏` → 顶部滑下难度抽屉（简单 40 / 普通 46 / 困难 52 / 大师 56 空，见 §4.2），选完直接开局；
  2. `继续游戏` → 进入未完成对局；**无存档时画虚线框并附一行淡墨说明**「暂无未完成的对局」；
  3. `退出游戏` → 二次确认（「退出游戏？」+ 取消 / 退出），并提示"未完成的对局会自动保存"。
- 底部：`InkGridSketch` + 一行淡墨小字「单机 · 无需联网」。
- 间距：标题上下各 `Xxl`；菜单项之间 `Md`；整体左右 `Lg`，内容最大宽 400dp 居中。
- **右上角**：明暗切换图标按钮（与对局页顶栏**同一枚图标、同一位置**，切页时它不会"跳走"），见 §11。
- **键盘导航**：菜单下方一行淡墨小字「↑↓ 选择 · Enter 确认」；`↑` / `↓` 在三个入口间循环移动
  （**自动跳过置灰的「继续游戏」**，与棋盘方向键"跳过给定格"同一套约定），`Enter` / 空格 确认；
  难度抽屉与退出确认抽屉同样支持（`Esc` 关闭），鼠标点击会把高亮同步过去，两种输入方式不打架。

### 3.2 骨架与提示：全自绘（无组件库）

| 能力 | 用什么 | 原因 |
|---|---|---|
| 页面骨架 + 安全区 | `App.kt` 的 `Box` + `Modifier.safeAreaPadding()` | 安全区做成 `expect/actual`：桌面恒为 0（无系统栏）；**启用移动端时必须补 actual，缺了会编译失败**，不会静默漏掉刘海与导航栏 |
| 一次性提示 | `InkSnackbarHost` / `InkSnackbarHostState` | 自绘墨条（上层纸片 + 手绘墨框 + `Ink.Type.Caption`），不拦截点击；保留"挂起排队"与"相同文案也算新的一条"两条语义（单测守着） |
| 配色 | `Ink` 对象 | 直接持有色值，不经主题上下文（此前那层主题包装从未被读取） |
| 图标 | `InkIcon` + `drawInkIcon` | 全部用 `inkLine` 与弧线**自绘**，不引图标库、不用图标字体（位图与字体图标在高 DPI 下会露馅，也换不出手绘感）。按钮只有 36dp，因此按**骨架差异**设计，不是细节差异：<br>· **返回** = 唯一**水平**的箭头（横杆 + 箭尖）<br>· **撤销 / 重做** = 互为镜像的**半圈**弧 + 箭尖<br>· **重置** = **接近一整圈**（300°）的弧 + 箭尖——弧长与"半圈"一眼分开<br>· **暂停 / 继续** = 两条竖杠 / 一个三角（同一位置切换，形状必须相反）<br>· **提示** = **灯泡**（灯罩 + 灯座 + 三道光线）——比"!"更不容易被读成"警告 / 错误"<br>· **太阳 / 月牙** = 圆 + 光芒 / 缺一段的圆（显示的是"点下去会变成什么"） |
| 图标悬停提示 | `InkIconButton` 的 `tooltip` | 鼠标移上去在按钮**正下方**浮出一张纸片（`Ink.Type.Meta`），移开淡出。**默认取 `contentDescription`**——它本来就是人话写的功能名，另造一个字段只会让两者慢慢走偏（读一个词、写另一个词是最糟的）。需要更短时才显式传（读屏念"切换到夜墨模式"，浮出来只写"夜墨模式"）。<br>两个约束：① 外层 Box **固定 36dp**，提示片是超出按钮范围的浮层——若让父容器按内容测量，悬停时会把顶栏撑高；② 提示片用 `wrapContentSize(align, unbounded = true)` 才不会被**按钮自己的 36dp 宽度**截断成"夜…"，并按 `tooltipAlignment` 决定往哪边长（贴窗口边缘的按钮必须显式给方向，否则会被窗口切掉） |

> 历史沿革：早期版本使用第三方 UI 组件库的**组件外观**，改版为"手写纸 · 简约油墨"后只保留它的骨架与提示通道，
> 现在这最后一点依赖也已移除——本工程**不引入任何第三方 UI 组件库**（尤其 Material3）：
> 填充色块、Material 圆角、开关轨道这类外观都与手写纸气质冲突，且会让依赖体积与风格同时分裂。
> 相关纪律见 `.codebuddy/rules/sudoku-dev.md` §3。

## 4. 对局页布局（`GameScreen`）

**一条纵列，三段**：顶栏 → 棋盘舞台 → 功能区。
设计目标是"**棋盘四周彻底空出来**"：核心区只有题面，一切控制项都在棋盘之外——
此前右侧立着一整块 360dp 控制栏（数字键盘 + 开关面板），棋盘被挤在一侧，
视线填一个数就要左右横扫一次。

```
┌─ 顶栏 56dp（横贯，全局操作唯一出口）──────────────────────────┐
│ ←(返回菜单)    难度·计时·提示次数·进度      💡 ‖ ↻ ☾/☀       │
├──────────────────────────────────────────────────────────────┤
│                  ┌─ 浮动操作条（撤销/重做）─┐                 │ ← 48dp 槽，跟着鼠标在
│                  └─────────────────────────┘                 │   上下两条槽之间搬
│                      ┌───────────────┐                       │
│                      │               │                       │
│                      │   棋盘（正方形）│  ← 左右两侧什么都没有  │
│                      │               │                       │
│                      └───────────────┘                       │
│                  ┌─────────────────────────┐                 │
│                  └─────────────────────────┘                 │
│                                                              │
│  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬─────┐  ← 功能区第一行：1–9 横向 + 擦除
│  │1 │2 │3 │4 │5 │6 │7 │8 │9 │擦除 │                          │
│  └──┴──┴──┴──┴──┴──┴──┴──┴──┴─────┘                          │
│  ☐笔记模式  ☑显示笔记  ☐候选提示  ☐严格模式  ← 第二行：四项偏好一行 │
└──────────────────────────────────────────────────────────────┘
```

- **顶栏**（`GameTopBar`，全高 56dp）——**全局操作的唯一出口**：
  左「返回菜单」图标 · 中「状态读数」（难度 / 计时 / 提示次数 / 进度，横排省高度）· 右「提示 · 暂停/继续 · 重置 · 明暗切换」四个图标。
  状态读数从"右上角一列"改到顶栏中间：它不属于操作、属于"看一眼"，横排更省高度。
- **棋盘舞台**（`BoardStage`）—— 上下各留一条 `FloatingBarSlot 48dp` 的槽给浮动条，中间是**强制正方形**的棋盘。
  正方形不是审美问题：`BoardCanvas` 按 `min(宽, 高)` 画网格，而语义层按"父容器 1/9"铺开，
  容器一旦不是方的，**读屏报出的格子就会与眼睛看到的格子错位**。
- **浮动操作条**（撤销 / 重做）—— 见 §4.1.1。
- **功能区**（`FunctionArea`）—— 与棋盘**同宽**、居中，压成两行：
  第一行 1–9 **横向**一排 + 「擦除」；第二行四项偏好开关**一行**排开。
  为什么开关不竖排：竖排要占 4×42 ≈ 170dp，棋盘就得再矮 130dp——而它们是"设一次就不管"的开关，
  不值得拿棋盘的尺寸去换（横排后整块功能区只有 102dp）。代价是每项只有棋盘宽的 1/4，
  因此标签一律控制在 4 个字以内、`maxLines = 1`。
- **棋盘尺寸的算法**：`boardSide = min(可用宽 − 2×Md, 可用高 − reserved)`，
  其中 `reserved` = 顶栏 + 上下留白 + 两条浮动条槽 + 间距 + 功能区 + 底部提示条预留。
  只给 `Modifier.width(boardSide)`——高度让内容（两条槽 + 正方形棋盘）自己决定；
  若用 `size()` 会把棋盘压扁成非正方形，语义层立刻与画出来的格子错位（见上）。
- **点棋盘以外的空白** → 棋盘回到开局的干净样子（清选中框 / 同行列宫高亮 / 同值高亮）。
  实现在内容下面垫一层 `matchParentSize` 的"空白层"承接点击：命中测试对**兄弟**是命中即剪枝，
  点到棋盘 / 按键 / 开关时命中的是上层那些节点，空白层根本不进事件链。
  （此前是在外层挂 `awaitFirstDown(requireUnconsumed = true)`，行为也对，但那个多出来的
  **父级指针节点会吃掉棋盘的悬停事件**——浮动条因此不再跟随鼠标。实机冒烟 `-Flow bar` 抓到的。）
- 暂停：用**白纸全遮棋盘**（不能继续读题）+ 居中「已暂停」与「继续」按钮；同时**清空 81 个格子的语义**
  （视觉遮了、读屏没遮 = 遮题只遮了一半）。
- 数字键盘：**1–9 横向等分、擦除占固定宽**（它是两个汉字，等分会被压得比数字键还窄）；
  每个键右上角用淡墨小字标注"该数字还剩几个"；数字用完时该键转为**淡墨框**（不靠颜色）。
- **通关结算抽屉**（`won == true` 时从顶部滑下，见 §4.2）：标题墨框「通关」+ 副标题「本局用时 mm:ss」，
  两行成绩（难度 / 提示次数，未用提示时写「未使用」），主操作「再来一局」（同难度重开）、次操作「返回首页」，
  底部淡墨提示「Enter 再来一局 · Esc 返回首页」。**不可点遮罩关闭**——避免误关丢掉结算信息。

### 4.1 悬浮输入面板（鼠标 / 触控笔）

**它解决什么**：数字键在棋盘**下方**，鼠标玩家每填一个数都要把指针移出棋盘再移回来。
点空格**就地**弹一个面板，指针不用长距离往返。

| 维度 | 规定 |
|---|---|
| 触发 | 点**空格**（非给定格）且指针是**鼠标 / 触控笔** → 选中该格并弹面板；点给定格只选中不弹；**手指不弹**（见 §6.1） |
| 内容 | **只列该格当前可填的数字**（`Sudoku.legalMask`），不列 1–9 全部。理由：一格通常只有 2–4 个候选，列全 1–9 既占地方又把键挤小；只列候选 → 键能做到 **48dp**（比早期 38dp 大 26%）、面板整体更小、更贴近落点。想记"不可能的数字"或擦除，用右侧常驻键盘（它始终在）。候选为 0 的极端格显示一行「本格无可填数字」，避免"点了没反应" |
| 位置 | 贴该格**右侧**、与该格垂直居中；右侧放不下翻到左侧；两侧都放不下贴右边缘；纵向始终 clamp 在棋盘内。算法是纯函数 `FloatingPadPolicy.placement`（有单测）。面板与棋盘放在同一个 `Box` 里，因此**窄屏滚动时随棋盘一起移动**，锚点不会失效 |
| 尺寸 | **不固定**：宽度 = 内边距 ×2 + 列数 × 键 + 间隔，列数 = `min(候选数, 3)`（1 个候选时只有一个键那么宽）；高度同理按行数算。键 48dp、间隔 6dp、内边距 10dp（`DesignTokens.Sizes.Pad*`，尺寸公式在 `FloatingPadPolicy.padWidth/padHeight`，有单测）。行内**居中**排布 |
| 样式 | 纸面 **94% 不透明**（能透出底下的格线，读作"浮着的一层薄纸"）+ 淡墨手绘边框 + 外侧错位 hairline —— 用**线**表达"浮起"，不用阴影；每个键都是"可填"，因此统一重墨框（没有"淡墨不可填"态）；不显示剩余计数角标 |
| 消失时机 | ① 填数之后；② 撤销 / 重做 / 提示 / 重置 / 暂停 / 切任一开关 / 回首页等**任何非选格动作**之后；③ 点另一格（面板跟到新格而不是关闭）；④ **再点一次同一格 → 收起**（`FloatingPadPolicy.nextOnCellClick`，toggle）；⑤ 点**棋盘以外的空白处**（与"清选中"同一个手势，见 §4 / §6）；⑥ `Esc`（**只收面板**，再按一次才走"暂停 / 继续"）；⑦ 暂停 / 通关 / 结算 / 回首页。②⑦ 由统一出口 `dispatch` + `FloatingPadPolicy.keepsOpen` 保证 |
| 保持打开 | 只有三类动作不关面板：`Select`（点棋盘选格）、`Move`（方向键换格，**面板跟着走**，键鼠混用不中断）、`SyncElapsed`（每秒心跳——否则面板会每秒闪一次） |
| 与键盘的关系 | 面板**不接管焦点**（焦点始终在棋盘容器上）：`1–9` 照常填数（填完同样收面板）、方向键照常换格且面板跟随、`Ctrl+Z` / `Ctrl+Y` 照常撤销重做。面板只提供"合法且更省力"的入口，**不削减能力**：想填一个明知错误或不在候选里的数字，用常驻键盘（它与面板走同一个 `Digit` action，严格模式下同样给 Snackbar 反馈） |

### 4.1.1 浮动操作条：撤销 / 重做跟着鼠标换边

**它解决什么**：撤销 / 重做是**高频、且紧跟着上一步操作**的两个按钮。把它们放进顶栏或棋盘下方的开关行里，
每撤销一手都要把指针搬出棋盘再搬回来——正是 §4.1 想消掉的那种往返，只是换了个对象。

| 维度 | 规定 |
|---|---|
| 位置 | **棋盘正下方**（默认）或**正上方**；上下各占一条 `Sizes.FloatingBarSlot`（48dp）的**专用槽**，条只在槽里出现，**绝不压在棋盘上** |
| 换边规则 | 鼠标进入棋盘容器**上方 35%** → 换到上方；进入**下方 65%** → 换到下方；中间 30% 是**滞回死区**（保持原样） |
| 为什么滞回 | 若按中线一刀切，鼠标停在中线附近轻微晃动就会让条来回跳——一跳，指着的"撤销"就换成了"重做"，误触代价不小 |
| 判据来源 | 相对**本容器**的纵坐标比例（`FloatingBarPolicy.next(previous, pointerY, boardTop, boardHeight)`），因此宽屏 / 窄屏都不需要外界传坐标 |
| 触屏 / 纯键盘 | 没有指针信息 → 保持默认**下方**（离手最近，也不挡题面第一行） |
| 宽度 | `fillWidth = false` **按内容收紧**：两个按钮撑满整宽会变成横贯棋盘的空白带 |
| 禁用态 | 跟着撤销 / 重做栈走：**栈空即虚线框**（不靠颜色），不需要额外状态 |
| 实现陷阱 ① | 容器高度必须用 `onSizeChanged` 记账后**在事件循环里读**。直接在 `pointerInput` 协程里读 `size.height` 会拿到 **0**（协程在首次布局前启动，且只在 key 变化时重启），表现为"条永远不动" |
| 实现陷阱 ② | 判据用**"指针没按下"**（`change.pressed == false`），**不要用** `event.type == PointerEventType.Move`：指针**刚进入**容器时 Compose 报的是 `Enter`、之后才是 `Move`，只认 `Move` 会漏掉"一步跨进棋盘"的情形（实机 `SetCursorPos` 正是这种），表现同样是"鼠标明明在棋盘上半部，条却不动"。用 `pressed` 还顺带排除了手指拖动——不会拿拖动的位置去挪条 |

> 这两条**都不是靠肉眼能定位的**：截图只告诉你"条在下面"，看不出是量不到高度、还是没收到事件。
> 因此换边行为由 `GameScreenUiTest`（真实组合 + 真实指针事件，含死区那一段）与冒烟流 `bar`
> 两张截图（`bar_at_top` / `bar_at_bottom`）**双重**守着。

### 4.2 顶部抽屉（`TopDrawer`）——覆盖层统一形态

**为什么用顶部抽屉而不是对话框**：覆盖层的三种内容（选难度、二次确认、通关结算）本质都是"从上方落下一张纸，请你先做决定"。
统一成一种形态后，视觉语言只有一套（纸 + 墨 + 遮罩），并且**能装的内容更多**：抽屉通栏、可纵向排开长列表，
不像居中对话框那样一长就要滚动。

| 维度 | 规定 |
|---|---|
| 结构 | 全屏遮罩（`Box(fillMaxSize)`）+ 贴顶纸片；纸片铺满窗口宽、内容限宽 `Sizes.DrawerMaxWidth`（560dp）并居中——宽窗口不拉成横带，窄窗口（移动端）自然满宽 |
| 遮罩 | `Ink.Black` × `Ink.Alpha.Mask`（16%），浓度随展开进度淡入；**只有展开时**才吃点击（收起后完全不拦截指针） |
| 纸片 | 白纸面；只做**下缘圆角**（上缘贴住窗口顶边，圆角推到屏幕外）；两圈手绘描边（淡墨 + 错位 hairline）表达"纸浮在页面之上"——墨线语言里没有阴影 |
| 抓手段 | 纸片顶部居中一条 44dp 短墨线（`Sizes.DrawerGripWidth`）：暗示"这是可以往下拉的一张纸" |
| 动效 | 滑入 240ms / 收起 180ms（`tween`），位移用 `graphicsLayer.translationY`——不参与布局，滑动过程零重组；不做弹跳与回弹 |
| 模态性 | 遮罩拦截指针（不穿透）；键盘由 `TopDrawerKeys` 仲裁：抽屉内未处理的键**一律吞掉**，不再落到下面的页面 |
| 键盘 | 页面根节点把每个键**先交给** `TopDrawerController.handleKey`（Compose 的 `onPreviewKeyEvent` 是父先于子，不仲裁就会"两面同时响应"）：`Esc` 且可关 → 关闭抽屉；不可关（通关）则由抽屉自己解释 `Esc`（返回首页） |
| 焦点 | 关闭时把焦点交回页面根节点（`restoreFocus`）——抽屉里的控件拿到过焦点，不移交会导致页面"按键失灵" |
| 无障碍 | 传 `a11yTitle` 时设置 `paneTitle`（读屏能读出面板名） |

## 5. 棋盘墨线表达（完全不用颜色）

| 信息 | 表达方式 |
|---|---|
| 题目给定数字 | **一墨**（`Ink.Black`）+ **数字族 Nunito**（印刷体），读作"印在纸上的题面" |
| 玩家填入数字 | **二墨**（`Ink.Grey`）+ **正文族霞鹜文楷**（手写体），读作"自己写上去的" |
| 冲突格 | **斜向排线**（`inkHatch`）+ 冲突数字外套一个**手绘圈**，并由 Snackbar 文案说明 |
| 选中格 | 双层手绘框（外粗内细）；**笔记模式下改为虚线框**（用线型区分模式） |
| 同值格 | 一层淡墨洗（`Alpha.Wash`） |
| 同行 / 同列 / 同宫 | 极淡墨洗（`Alpha.Hair × 0.55`） |
| 笔记（候选数） | 3×3 排布的小号淡墨**实心**数字（玩家自己记的） |
| 候选提示（规则允许的数字） | **所有空格**都用同一套 3×3 排布写出候选，墨色是**半透明灰**（`Ink.Grey` 42%）——比笔记更淡，读作"背景信息"；已有笔记的格子显示笔记（玩家自己的判断优先）。开关关闭时完全不画 |
| 网格 | 细线 `Grid` + 每 3 格加粗 `GridBold`；整盘外套手绘粗框 |
| 底层 | 棋盘铺纯白（与页面暖白纸形成极淡层次） |

数字字号用 `toSp()` 由格子像素换算（`DrawScope` 本身是 `Density`），因此在任何 DPR / 字体缩放下都与格子等比。

### 5.1 为什么要区分「给定」与「填入」

**问题**：两类数字只靠墨色深浅（一墨 vs 二墨）区分时，在**浅色纸**上仍会看混——
玩家回头找自己填的那一格，得逐格比对浓淡，这正是"看不清哪些是自己填的"。

**做法：三重信号同时给，任取其一都分得开**

| 信号 | 给定 | 填入 |
|---|---|---|
| 墨色 | `Ink.Black`（一墨，17.4:1） | `Ink.Grey`（二墨，9.1:1） |
| 字形 | 数字族 **Nunito**（印刷体，圆润匀称） | 正文族 **霞鹜文楷**（手写体，带笔锋与倾斜） |
| 读屏 | "…，**给定** 5" | "…，**填入** 9" |

**为什么用字形而不是字重**：包里只打了一份 Nunito（Regular），
请求 `FontWeight.Bold` 会**退回系统字体**——那不是"加粗的给定数字"，而是"给定数字换了一副字形"，
看起来更像 bug 而不像设计。改用"数字族 vs 正文族"是**两族都在包里、都确定存在**的对比。

**为什么不动整体观感**：两种字形都是同一套手写纸语言里的（一个管数字、一个管正文），
墨色仍是纸墨两级，没有引入颜色、没有加粗描边，棋盘在缩略看一眼时依然是"一张安静的九宫格"。

## 6. 交互与键盘

| 操作 | 行为 |
|---|---|
| 首页 | 三个入口 + 难度遮罩 + 退出确认（见 §3.1）；↑↓ / Enter / Esc 键盘操作 |
| 选格 | 点棋盘格 → `Select(pos)`；鼠标 / 触控笔点空格还会弹出悬浮输入面板（§4.1） |
| 清临时标记 | 点**棋盘以外的空白** → `Deselect`：选中框、同行列宫高亮、同值高亮一起消失，棋盘回到开局那样干净。**只清"选中"这一项**——盘面 / 笔记 / 计时 / 提示次数 / 撤销栈一律不动（选中的高亮都从 `selected` 派生，清掉它就全没了）。**冲突排线也不清**：那是对局数据（真的填重了），清掉等于骗玩家。实现在内容下面垫一层可点空白（见 §4），**不靠事件消费的博弈** |
| 候选提示 | 选项面板的「候选提示」开关（**默认关闭**）：开=**所有空格**显示规则允许的数字（半透明灰小字），关=不显示 |
| 填数 | 点数字键 / 键盘 1–9 → `Digit(value)`；再次点同数字清除 |
| 擦除 | `Digit(0)`（键位「擦除」/ `0` / `Delete` / `Backspace`） |
| 笔记 | 笔记模式下的数字键切换候选位；落子自动清理同行列宫候选 |
| 提示 | `Hint` 填入正确数字，状态行累计「提示 ×N」 |
| 重置 | 清空玩家填入与提示计数并重新计时（可撤销） |
| 撤销 / 重做 | 恢复 / 重放快照（上限 300 步） |
| 暂停 | 停表 + 白纸遮题；`Esc` / 空格 继续 |
| 通关 | 填满正确盘面 → 从顶部滑下**通关结算抽屉**（用时 / 难度 / 提示次数 / 再来一局 / 返回首页，见 §4.2） |
| 再来一局 | `NewGame(同难度)`：全新题面、计时归零、撤销栈清空，**但五项偏好保留**（严格模式 / 显示笔记 / 笔记模式 / 候选提示 / 夜墨模式） |
| 看答案 | `Reveal`：reducer 已实现并有单测，**UI 未接入**（改版后未放入任何菜单） |

桌面键盘映射（`GameScreen.handleKeyEvent`）：`1–9` 填数、`0`/`Delete`/`Backspace` 擦除、
方向键选格（**自动跳过给定格**）、`N` 笔记、`H` 提示、`P`/空格 暂停、`Esc` 继续 / 收面板、
`Ctrl+Z` 撤销、`Ctrl+Y`（或 `Ctrl+Shift+Z`）重做；
**通关时**只保留 `Enter`（再来一局）与 `Esc`（返回首页），撤销 / 重做仍可用（撤销即退回通关前）。
首页键盘映射见 §3.1。

**候选提示开关的切换反馈**：① 手绘勾选框出现 / 消失；② **全盘所有空格的候选数字同时出现 / 消失**——
反馈立刻可见，因此**不需要**顺手移动玩家的选中格（设置类开关不该改选中状态）；
③ 该行下方一行淡墨小字说明当前含义（关：「开：在空格里显示可填数字（半透明灰）」；
开：「空格里的半透明灰数字 = 规则允许的候选」）；④ 切换时给一条 Snackbar 文案
（与其它开关的"只看勾选框"略有不同，因为这项改变的是**棋盘上的信息量**，值得显式确认）。

### 6.1 候选数字与输入入口：鼠标 / 触屏两套方案

| 维度 | 鼠标 / 触控笔（桌面） | 触屏（移动端） |
|---|---|---|
| 候选数字展示 | ① **所有空格**里的半透明灰候选数字（候选提示开启时）；② 常驻数字键盘：非法数字淡墨框；③ 悬浮面板：只列可填数字（全是重墨框） | ① **同一套**半透明灰候选数字（渲染路径完全相同，`core` / `state` 零差异）；② 常驻键盘非法数字淡墨框 |
| 数字选择入口 | **悬浮面板（就近，只列可填数字）+ 常驻键盘**并存——鼠标用面板省往返，习惯键盘的用户不受影响 | **常驻底部数字键盘**：点格只选中，不弹浮层 |
| 两者是否重复 | **不重复**，是两条互补路径（结论见下方"冗余检查"） | 只有一条路径，天然无此问题 |
| 为什么不同 | 指针精确且不遮挡落点，就近面板收益最大 | 手指会遮住落点附近的一切：面板只能放到"手指之外"，而那个位置必然离格子很远，等于绕回底部键盘——不如一步到位用常驻键盘（移动端的拇指本来就在底部） |
| 输入设备判定 | `PointerType.Mouse` / `Stylus` | `PointerType.Touch`（`BoardCanvas` 在按下时判定并回传给调用方，见 `FloatingPadPolicy.shouldOpen`） |
| 移动端待补（M2） | — | ① 命中区放大到 ≈1.25 格（数独格子仅 ~40dp，指尖精度不足）；② 选中格上方一条"候选预览条"贴住键盘，指腹不动即可点；③ 长按空格 = 记笔记（免切笔记模式） |

> 两套方案共用同一份状态与渲染：`hintCandidates` 开关、`legalMask`、空心候选绘制都在 `core` / `state` / `ui` 的公共代码里，
> 平台差异只有"要不要弹面板"这一个布尔判定——新增平台时不必重做候选逻辑。

**冗余检查（桌面鼠标有三个输入入口：悬浮面板 / 常驻键盘 / 物理键盘）**

结论：**三者不是重复，删任何一个都会留下功能缺口**，但确实查出过两处"真重复"并已修掉。

| 入口 | 不可替代性 |
|---|---|
| 悬浮面板 | **就近**：指针不用移出棋盘。但它只列合法候选 → **擦除和"记不可能的数字"它做不到** |
| 常驻键盘 | 鼠标 / 触屏 / 键盘三态通用；有**剩余计数**与**擦除**；笔记模式下要能记 1–9 全部 → **不能被面板替代** |
| 物理键盘 | 不用指针；与"方向键移动选中格"的键盘模型配套 |

已修掉的两处真重复：

1. **同一时刻屏幕上两个键盘过滤出同一份候选**（选中格时常驻键盘也按 `legalMask` 变灰）——
   保留这个过滤（它是有用的护栏，避免误填），但**把两份重复的 `legalMask` 计算合并为按盘面缓存的一次**
   （计时每秒重组一次，不缓存就是每秒白扫一遍 81 格）。
2. **面板关不掉的死角**：此前只能靠 `Esc` 或点棋盘外的面板区关闭，在棋盘上"再点一下"没有任何反应。
   已按最自然的手势补上 toggle（见 §4.1 "消失时机" ④）。

**刻意不做**的是"悬浮面板出现时自动隐藏常驻键盘"：那会让"擦除 / 记任意数字"在鼠标路径下无处可去，
而且面板显隐会引起布局跳动——**布局跳动比功能重复更伤体验**。

## 7. 无障碍

- **对比度（两套主题都达标）**：对**棋盘纸**实测（WCAG 2.1 相对亮度公式，量算脚本见 `docs/07` §5）：

  | 墨 | 纸墨（浅底） | 夜墨（深底） | 门槛 |
  |---|---|---|---|
  | 一墨（主墨 / 给定数字） | `#1B1A17` **17.40:1** | `#F0ECE3` **14.44:1** | ≥ 4.5（AA 小字），实际超 AAA |
  | 二墨（填入数字 / 次要） | `#4B4843` **9.10:1** | `#C9C3B8` **9.71:1** | ≥ 4.5 |
  | 三墨（可当正文） | `#6A655C` **5.79:1** | `#A39D93` **6.32:1** | ≥ 4.5 |
  | 四墨（**仅禁用态**） | `#8B867C` 3.62:1 | `#767068` 3.48:1 | WCAG 对禁用控件不要求；两套特意调到**观感一致** |

  这条底线由 `InkThemeTest` 钉住（**不是靠肉眼**：把色值改浅一档几乎看不出来，但低视力用户会直接读不清）：
  两套主题的前三级必须 ≥ 4.5:1，四墨必须"看得见（≥3:1）且确实够淡（<4.5:1）"——后者防止它被误用成正文色。
- **不依赖颜色**：冲突用排线 + 手绘圈 + 文案；禁用用虚线框；可填性用线重；模式用线型；
  "自己记的笔记"与"系统算的候选"用**墨色深浅**区分（笔记是实墨小字，候选是半透明灰小字）。
- 悬浮输入面板只是鼠标的**快捷键**：键盘有完全等价的入口（1–9 / 0 / 方向键 / Ctrl+Z），
  面板本身不接管焦点、不改变任何玩法规则，因此不会造成"没有鼠标就用不了"的功能缺口。
- 棋盘是**两级语义**：
  ① 整盘节点（难度 / 已填进度 / 是否暂停 / 是否笔记模式 / 当前选中行列）；
  ② **格子级节点 9×9 = 81 个**，读屏可逐格朗读「行列 + 状态 + 内容」，
  例：`第 1 行第 1 列，已选中，给定 5` / `第 3 行第 5 列，空，笔记 1、3` / `第 4 行第 2 列，填入 7，与同行列宫重复`。
  实现见 `BoardCanvas.kt` 的 `BoardCellSemantics` / `cellA11yLabel`（文案是纯函数，单测覆盖）。
- **语义格必须与画出来的格逐格对齐**（修掉过一桩真缺陷）：那 9×9 语义网格用 `weight(1f)` 等分，
  **不要用 `fillMaxHeight(1f/9f)` / `fillMaxWidth(1f/9f)`**——Column / Row 给子项的是**"剩余"**空间，
  `fillMax*` 于是逐行（逐列）缩水，9 行只铺满约 **65%**，后果是"读屏念第 5 行第 5 列、点下去却选到第 4 行第 4 列"。
  **偏差越往后越大**：这条缺陷长期没被发现，正是因为它当时只被"第 2 行第 2 列"那条用例覆盖——
  前两三行的偏差还不到一格，正好蒙对。用例已改为拿**最后一格**当哨兵（`BoardCanvasUiTest`），
  并在 `GameScreenUiTest` 里从第 5 行第 5 列反向验证"点格子回传的就是这一格"。
- 格子**刻意不做可 Tab 聚焦**：本作键盘模型是"方向键移动选中格"，再加 81 个 Tab 停靠点会毁掉键盘体验；
  读屏用户用"朗读下一项"即可逐格遍历（语义节点不需要 `focusable()` 也能被 TalkBack / NVDA 到达）。
- **不朗读系统候选**（`hintCandidates`）：候选是冗余通道（悬浮面板与键盘都能拿到同一信息），
  逐格念 9 个候选会把行列与值淹没；玩家自己记的笔记要念——那是他的判断。
- 所有可点控件统一带 `Role`、焦点态与键盘可达性（Tab 序由 Compose 自动管理）。
- 键盘高亮态**不是唯一线索**：首页同时有「↑↓ 选择 · Enter 确认」文字说明，通关墨框同理；
  即使用户看不到墨洗差异，也知道当前在哪一项。
- **尊重系统"减少动态效果"**：开关打开时，抽屉动画、按压反馈与**开局显影**的时长一律变为 **0（瞬时就位）**，
  不做"半速播放"（半速对前庭敏感的用户更难受）。开局显影还额外**初始即"已显影"**，
  因此不会出现"先空一帧再出现"的闪烁。判定与覆盖方式见 `docs/03` §"实机冒烟"；
  策略函数 `motionDurationMs(baseMs, reduceMotion)` 是纯函数，单测覆盖。

## 8. 应用图标

图标是这套视觉语言在"应用之外"的唯一出口（任务栏、桌面、商店），因此单独立规：

- 主体为**一个九宫格 + 数字**（四角给定 + 中心灰色"玩家填入"），部分填、部分空，一眼读作数独；
- **不使用任何"落子"形态**（无实心圆点、无对角连珠、无黑白对峙），与五子棋 / 围棋明确区分；
- 配色只有纸 `#F7F5F0`、墨 `#1B1A17` 与一档中灰 `#4B4843`，与界面同源；
- 细节随尺寸递减（数字 5 → 4 → 2 → 1 个），16px 也保留"格子 + 数字"两个要素；
- 生成、尺寸规范、各平台产物清单与验收方式见 **`docs/06-应用图标设计.md`**。

## 9. 设计令牌：全站唯一出口

任何视觉常量都必须来自下面三处之一，**不允许在调用点写裸值**（评审与整改记录见 `docs/07`）。

| 类别 | 出口 | 内容 |
|---|---|---|
| 颜色 · 透明度 · 字体 · 排版 · 主题 | `Ink`（`ui/theme/Ink.kt`） | 主题开关 `isDark` / `setDark`（快照状态）；纸三层 `Paper` / `PaperShade` / `PaperSheet`；墨四级 `Black` / `Grey` / `Light`（可当正文，≥ AA）/ `Faint`（仅禁用态）；模态遮罩 `Scrim`；`Alpha` 七级 + `Hint` / `Sheet` / `Decor`；**`Type` 六档**；图标 `InkIcon`。**除 `Scrim` 外每个色名都有浅 / 深两套值** |
| 间距 · 圆角 · 尺寸 · 线宽 · 动效 | `DesignTokens`（`ui/theme/DesignTokens.kt`） | `Spacing` 六档（4/8/16/24/32/48）；`Radius` Mark/Cell/Button/Panel；`Sizes`（断点 / 控件高 / 棋盘下限 / 抽屉宽…）；`Stroke` Hair/Thin/Bold/Frame/Grid/GridBold/Selection/Hatch；`Motion` Press/Reveal/Enter/Exit |

**铁律**

1. **排版只有六档**（`Ink.Type`）：`Meta 12` · `Caption 14` · `Body 16` · `Title 20` · `Headline 28` · `Display 40`，
   每档自带字距与行高。**正文层级只靠"字号 + 字距 + 墨的浓淡"**——手写体没有真 Bold，合成粗体会发虚，破坏手绘工艺感；
   例外：**数字**（Nunito，有真实字重）可用字重分层（给定数字 = Medium、填入 = Normal），见 §2.3。
2. **纸只走三层、墨只走四级**：层级用"纸的深浅 / 墨的浓淡"表达，**禁止阴影、渐变、彩色状态**。
   新增纸或墨之前先问："现有的层级能不能表达？"能就不加。
3. **可读性硬线**：`Light` 及以上必须对三种纸底都 ≥ 4.5:1（WCAG AA 小字）；`Faint` 只能用于禁用态文字
   （WCAG 对禁用控件不要求对比度）。**两套主题各自独立达标**——夜墨不是把浅色反相，
   而是要单独校准到同一水平（实测见 §7）。改任何色值前先跑对比度量算（`docs/07` §5），
   并确认 `InkThemeTest` 仍然全绿。
4. **线宽只有一个出口**（`DesignTokens.Stroke`）：不要派生"差不多"的宽值（如 1.1 / 1.3 混用）；
   需要新档先加令牌并写清用途。
5. **动效只有四档**（`Motion`）：`Press 90` 即时反馈、`Reveal 160` 开局显影、`Enter 240` 覆盖层进入、
   `Exit 180` 退出。两条语义约束：**退场必须快于进场**、**开局显影 ≤ 200ms**（`docs/07` §4 的验收线）。
   手绘风格不用弹跳过冲，统一 `tween` 默认缓动。
6. **图标与界面同一套几何**：图标的比例 / 线宽 / 圆角与界面令牌对齐（`docs/06`），改一处要检查另一处。

## 10. 窗口与自适应

- 桌面窗口默认 1180×900、最小 940×720（`jvmMain/main.kt`：`rememberWindowState` + `window.minimumSize`）。
- **没有断点**：对局页只有一条纵列，靠"棋盘边长 = `min(可用宽, 可用高 − 预留)`"自适应，
  宽窗口时棋盘居中、两侧留白，窄窗口时棋盘缩到还剩得下的尺寸。
  因此**窗口比例怎么变都不会出现"第二种布局"**——少一套布局就少一套要各自验收的形态。
- 验收窗口档位（每次 UI 改动都要过）：1180×900（桌面默认）、800×600（小窗）、500×1000（手机竖屏比例）、
  平板横屏（1024×768）。
- 高 DPI：尺寸一律 dp / `toSp()`；线宽用 dp 换算，禁止裸像素。

## 11. 主题与配色策略

**两套主题，玩家手动切换，不跟随系统。**

| | 纸墨（默认） | 夜墨 |
|---|---|---|
| 底纸 / 压印 / 上层纸片 | `#F7F5F0` / `#EDE9DF` / `#FFFFFF` | `#121110` / `#0B0A09` / `#1E1C17` |
| 一墨 / 二墨 / 三墨 / 四墨 | `#1B1A17` / `#4B4843` / `#6A655C` / `#8B867C` | `#F0ECE3` / `#C9C3B8` / `#A39D93` / `#767068` |
| 模态遮罩 | `#000` × 16% | `#000` × 46% |
| 观感 | 暖白纸 + 近黑墨 | 暖近黑纸 + 暖近白墨 |

- **为什么不是"自动跟随系统深色"**：手写纸风格以"纸"为前提，而系统深色是**暗色 UI**语义；
  本作的夜墨是"**在暗处也能写的另一种纸**"，两套都是成品设计，需要各自校准对比度。
  跟随系统还会带来一个问题：用户无法在本作里覆盖系统设置做"白天用纸墨、晚上用夜墨"。
- **切换入口**：首页与对局页**右上角同一位置**同一枚图标（月亮 / 太阳），切页时它不会"跳走"。
- **持久化**：`darkMode` 是第五项跨对局偏好，随存档落盘（`SaveCodec` v2 新增一行；旧存档缺行 → 取"浅色纸面"，
  与升级前的观感一致）；**新开一局继承**，不会被 `NewGame` / 重置 / 通关清回默认。
- **实现约束（踩过的坑，改动前务必先读）**：

  | 约束 | 原因 |
  |---|---|
  | 主题状态用**快照状态**（`Ink.isDark` + `setDark`），**不用 `CompositionLocal`** | `Ink.*` 也会被 `DrawScope` 里的绘制原语读到（`Canvas { drawRect(Ink.PaperSheet) }`），`CompositionLocal` 在绘制阶段取不到；快照状态在组合与绘制两处都能订阅 |
  | 色值一律写成 **getter**，禁止 `val X = Color(...)` 缓存 | 一旦在 `object` 初始化时算好，切主题后就停在旧色。`Ink.Type` 六档同理（`style()` 会把颜色烤进 `TextStyle`） |
  | 遮罩必须走 `Ink.Scrim`，不能写 `Ink.Black.copy(alpha)` | 夜墨下 `Black` 是近白色，拿它当遮罩会变成一层**白光** |
  | 唯一写入点：`App.kt` 的主题同步（值与偏好不同才写） | 放在最前面同步，同一帧内后续子组件读到的都是新配色，不会"先按浅色画一帧再翻成夜墨" |
  | 新增配色**必须同时给两套值**，并重算对比度 | `InkThemeTest` 会在夜墨下前三级跌破 4.5:1 时失败 |

- Monet 动态取色与彩色语义色**不适用于本风格**，不启用（两套主题同样"只有纸与墨"）。
