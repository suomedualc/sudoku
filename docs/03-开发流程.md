## 1. 环境准备

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | 17+（本项目用 21） | **启动 Gradle 的 `JAVA_HOME` 必须是 JDK 17–24**；JDK 25 会让 Gradle 8.12 直接失败（报错只有版本号一串，极易误判） |
| Gradle | 8.12（wrapper 已入库） | 直接 `.\gradlew.bat`，无需本机安装 |
| Kotlin | 2.4.0（由 Gradle 插件拉取） | 与 CMP 1.11.1 对齐 |
| Android SDK | 仅启用 Android 目标时需要 | `D:\env\Android-SDK`（`local.properties` 里的 `sdk.dir`） |
| 第三方 UI 库 | 无 | 骨架 / 控件 / 提示全部自绘，见 `docs/02` §3.2 |

工具链要求：把 **`JAVA_HOME` 指向 JDK 21**（17–24 皆可）——`jvmToolchain(21)` 会复用这个 JVM，
所以仓库里不写死任何本机路径。若 JDK 21 不在 `JAVA_HOME` 或不在标准位置，在**用户级**
`~/.gradle/gradle.properties` 声明（**不要写进仓库**，否则暴露本机路径且对他人无效）：

```properties
# 本机 JDK 21 不在标准位置时：同时固定守护进程 JVM 与工具链解析
org.gradle.java.home=D:/path/to/jdk-21
org.gradle.java.installations.paths=D:/path/to/jdk-21
```

`org.gradle.java.home` 值得单独说明：有了它，**即使 `JAVA_HOME` 被改错（如指向 JDK 25），构建也不会失败**
（已实测：`Daemon JVM: … (from org.gradle.java.home)`，`BUILD SUCCESSFUL`）。Gradle 用 wrapper（8.12）即可，无需本机安装。

```powershell
$env:JAVA_HOME="<你的 JDK 21 路径>"
.\gradlew.bat :composeApp:jvmTest --offline --console=plain
```

## 2. 版本对齐（关键）

`gradle/libs.versions.toml` 当前锁定：

```
kotlin                 = 2.4.0
compose-multiplatform  = 1.11.1
```

约束关系：**Kotlin 与 CMP 由同一版本目录锁定**，2.4.0 + 1.11.1 是一组已验证可用的搭配。
（历史教训：曾用 Kotlin 2.1.20 / CMP 1.8.0 编译失败，升级后通过。）
`gradle/libs.versions.toml` 里**不声明任何第三方 UI 组件库**——骨架、控件与提示全部自绘，
因此不存在"库与编译器强绑定"的约束。此前曾有一个第三方 UI 库要求 Kotlin / CMP / 自身三者整体对齐，
且 Android 侧强制 `compileSdk 37`；该依赖已移除，过程见 `docs/05` §5.8。
Kotlin 2.5 起将要求 Gradle ≥ 8.14.4，升级 Kotlin 时需同步换 wrapper。

## 3. 构建与运行

Gradle wrapper（8.12）已入库，统一使用：

```bash
.\gradlew.bat :composeApp:run                     # 桌面运行
.\gradlew.bat :composeApp:compileKotlinJvm        # 编译
.\gradlew.bat :composeApp:jvmTest --offline       # 单元测试 + UI 测试（129 项）
.\gradlew.bat :composeApp:createDistributable     # 自带 JRE 的分发目录（binaries/main/app/SudokuInk）
.\gradlew.bat :composeApp:packageMsi              # Windows 安装包（首次需联网下载 WiX，约 99 MB）
```

打包约定（2026-10-06 实测通过，产物 `SudokuInk-2.0.0.msi` 约 60 MB，产品名 / 制造商 / 图标均正确）：

- `packageName` **必须纯 ASCII、无空格**（jpackage 会把它当产品名、安装目录名与 MSI 标识；旧值 `"数独 Sudoku"` 有失败风险）。
- `description` / `vendor` / `copyright` 在 `composeApp/build.gradle.kts` 的 `nativeDistributions` 里声明。
- 图标：由 `tools/make-icon.ps1` 一次生成三处产物（设计说明见 `docs/06-应用图标设计.md`）：
  ① `composeApp/icons/sudoku.ico`（16/20/24/32/40/48/64/96/128/256 共 10 档）→ `windows { iconFile }`；
  ② `composeApp/icons/sudoku.png`（256）→ `linux { iconFile }`；
  ③ `composeApp/icons/sudoku-NN.png`（16/24/32/48/64/128）→ **运行时窗口 / 任务栏图标**（进 jar）；
  另有 `assets/icon/` 输出桌面 / Android / iOS / macOS / Web 各平台规格与矢量源（`source/sudoku.svg`）。
  构图是**九宫格 + 数字**（4 角给定 + 中心灰色"玩家填入"），细节随尺寸递减。
  **改视觉后重跑一次脚本 + 重新打包**即可。macOS 的 `.icns`（含 `.iconset`）已由脚本产出并接入打包
  （`iconutil` 仅限 macOS，此处由脚本自行组装；**未在 macOS 上做渲染实测**，见 `docs/06` §9）。
- **图标要设两次，缺一不可**（2026-10-06 实测踩到）：
  ① 打包期 —— `nativeDistributions` 的 `iconFile`，jpackage 把它嵌进 **exe 文件**（资源管理器里看得到）；
  ② **运行期** —— jpackage **不会**改窗口图标，AWT 创建的窗口仍用 JDK 的 Java 图标（标题栏与任务栏都显示它），
  所以 `jvmMain/main.kt` 里必须 `window.iconImages = …`。这些 PNG 通过 `jvmMain { resources.srcDir("icons") }`
  打进 jar（与打包图标**同源**）；读取用 `Class.getResourceAsStream("/sudoku-32.png")`，
  **不要用 `ClassLoader.getResourceAsStream`**（它不接受以 `/` 开头的名字，会静默返回 null → 图标设不上）。

### 3.1 Windows 试运行（三种方式，按"临时 → 正式"排序）

| 方式 | 命令 / 操作 | 适用 | 注意 |
|---|---|---|---|
| ① 开发运行 | `.\gradlew.bat :composeApp:run` | 改代码后立即看效果 | 依赖本机 JDK 21（已由用户级 `~/.gradle/gradle.properties` 固定）；关掉控制台即退出 |
| ② 便携版（推荐日常试玩） | `.\gradlew.bat :composeApp:createDistributable` → 双击 `composeApp\build\compose\binaries\main\app\SudokuInk\SudokuInk.exe` | 不带开发环境体验完整程序 | **自带 JRE**，拷到别的 Windows 机器也能跑；整个 `SudokuInk` 目录一起拷 |
| ③ 安装包 | `.\gradlew.bat :composeApp:packageMsi` → 运行 `composeApp\build\compose\binaries\main\msi\SudokuInk-2.0.0.msi` | 验证安装 / 卸载、开始菜单与图标 | 首次需联网下载 WiX（约 99 MB）；安装需要管理员权限 |

运行期事实（三种方式一致）：

- 存档：`%USERPROFILE%\.sudoku-ink\save.txt`（纯文本，删掉即清空续局；格式见 `docs/01` §5）。
- 窗口：默认 1180×900、最小 940×720；窗口最小化会自动暂停计时。
- 退出：首页「退出游戏」→ 确认，或直接关窗（未完成对局已自动存盘）。
- 纯键盘可走完：首页 `↑↓` + `Enter` → 对局 `1–9` / 方向键 / `Ctrl+Z` → 通关 `Enter` 再来一局。

## 4. 目录约定

- `core/`：纯算法，**禁止** IO / 时钟 / UI / 平台 API。
- `state/`：纯状态机，**禁止** Compose / 平台 API；随机源以参数注入。
- `ui/`：仅此层可调用 Compose / Canvas。
- 平台入口放在 `androidMain` / `jvmMain`，仅做装配。
- `tools/`：构建期辅助脚本（`make-icon.ps1` 生成图标、`get-fonts.ps1` 拉取字体、`smoke-e2e.ps1` 实机冒烟），
  **不参与编译**；图标产物落在 `composeApp/icons/`，字体落 `composeApp/src/jvmMain/resources/fonts/`（24.4MB 霞鹜文楷 + Nunito + OFL，
  属**分发资产**，用 `get-fonts.ps1` 复现来源与版本；授权见 `docs/02` §2.3）。
- 仓库根不放截图、日志、构建产物：`build/`、`.gradle/`、`.kotlin/` 均已在 `.gitignore` 中。

  **策略与接线要分开测**：策略是纯函数（好测），但真正出过两次 bug 的是**接线**
  （读 `size.height` 拿到 0、只认 `Move` 漏掉 `Enter`），两次都只有真机 / 这条 UI 测试才暴露。
- **运行方式**：`.\gradlew.bat :composeApp:jvmTest --offline`（当前 **129 项全绿**，含 13 项 Compose UI 测试：
  `TopDrawerUiTest` 4 键盘路由 + `BoardCanvasUiTest` 6 格子语义、点击穿透、暂停遮读屏与显影不吃点击
  + `GameScreenUiTest` 3 浮动条换边、点空白清标记、图标悬停提示）。
  注意：UI 测试依赖 `compose.uiTest`（`jvmTest.dependencies`），**首次需要联网**拉一次该 artifact；
  拉到本地缓存后 `--offline` 照常可用（与项目其它依赖同一套规则）。
- **覆盖层约定**：新页面不要再引 `Dialog` / `Popup` / 自造遮罩——统一用 `TopDrawer` + `TopDrawerController`，
  页面根节点在 `onPreviewKeyEvent` 里先 `drawer.handleKey(event, drawerKeys)` 再处理自己的键（见 `docs/02` §4.2）。
- **减少动态效果（reduced-motion）**：判定在 `expect fun prefersReducedMotion()`（桌面实现在 `Motion.jvm.kt`：
  先读 JVM 参数 `-Dsudoku.reduceMotion` / 环境变量 `SUDOKU_REDUCE_MOTION`，再读系统设置——
  Windows `VisualFXSetting=2`、macOS `reduceMotion=1`、GNOME `enable-animations=false`；查不到就当"不减少"）。
  所有动画时长必须过 `motionDurationMs(baseMs)`（开启时**返回 0**，不做半速播放）。
  验收方式：用环境变量跑同一操作、在同一时刻截图对比（开启时抽屉应已整块就位）。
- **动视觉先动令牌**：改字号 / 颜色 / 线宽 / 圆角 / 动效时长，一律先改 `Ink` 或 `DesignTokens`（铁律见 `docs/02` §9），
  再到调用点引用；改色值前必须跑一次对比度量算（< 4.5:1 就不能当正文用）。设计类改动的评审与复核清单见 `docs/07` §5。
- **实机冒烟（置顶 + 固定坐标）**：`.\gradlew.bat :composeApp:createDistributable --offline` 之后
  运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools\smoke-e2e.ps1`。
  它会：把应用窗口 `HWND_TOPMOST` 钉在 (100,100) 1180×900 → **每次注入按键/点击前断言"前台就是它"**
  （不是就直接中止，绝不盲发）→ 按窗口矩形截图。  覆盖**八条流**：难度抽屉（Enter 开、↓↓ 到"困难"、Enter 开局）、
  退出确认（↓ + Enter 真的退出进程）、通关抽屉（注入"只差一格"存档 → `H` 提示补满 → 通关抽屉 → `Esc` 回首页）、
  夜墨（注入带 `darkMode=1` 的存档 → 开局即夜墨 → **点右上角图标切回浅色**）、
  浮动条（只移动指针不点击：移到棋盘上半部 / 下半部，各截一张图验证条真的换边）、
  交互细节（悬停顶栏图标 → 浮出功能名；点棋盘中心 → 选中 + 高亮；**点棋盘外的空白 → 高亮全消**；
  选末格填 9 → 对比"印上去的给定"与"写上去的填入"）、
  键盘光标（注入"末尾 4 格空白"的存档 → 开局光标落在读序第一个空格 → → 走到下一个空格 →
  填 1 / 7 / 9 逐格跳转 → **宫 8 填满后跳回宫 7 里的 77**，5 张截图逐步核对）、
  键位自定义（底部提示行默认样子 → 开键位设置抽屉 → 点「向上」进捕获态 → 按 W 绑定 →
  再把「向右」绑到 D → 关抽屉 → **提示行实时变成「W」「↓」「←」「D」** → 按 D 光标真的右移一格，7 张截图）。

  **写按键时容易踩的两个坑**（都真踩过）：
  ① 方向键必须传扩展位（`Send-Key $p 'Right' $script:KeyExtended`），漏了窗口收到的不是方向键——
  表现为"脚本按了、应用没反应"，很容易误判成应用有 bug；
  ② 虚拟键码别凭印象写（脚本里 `Left` / `Right` 曾经写反：`VK_LEFT = 0x25`、`VK_RIGHT = 0x27`）。
  脚本会**先备份再恢复**玩家存档 `~/.sudoku-ink/save.txt`（`-Flow menu|exit|win|theme|bar|all` 可选单跑）。
  截图可用性判定接受**两套主题**（纸墨偏亮 / 夜墨偏暗）；落在两者之间的"中间灰"仍判为可疑——
  那正是被别的窗口盖住 / 锁屏的样子。
  为什么必须置顶：OS 级注入（SendKeys / keybd_event / PostMessage / 坐标点击）只对**真正持有前台**的窗口有效，
  桌面有别的窗口时应用会中途失焦，注入的输入会打到别人的窗口上（踩过：点击落到了浏览器窗口）。
  另外方向键必须带 `KEYEVENTF_EXTENDEDKEY`，否则会被当成小键盘键。脚本保持 **ASCII-only**（PS 5.1 无 BOM 时按 ANSI 解析）。
- **UI 层**：已有 **10 项 Compose UI 测试**（键盘路由 4 + 棋盘语义 / 点击穿透 / 显影 6，见上）。
  **自动化测试覆盖不到的**仍要键鼠试玩 + 系统截图，清单：
  ① 三档窗口（1180×900 双栏 / 800×600 纵向滚动 / 500×1000 手机竖屏）；
  ② 纯键盘走完「↑↓ 选入口 → Enter 进局 → 方向键选格 → 数字填数 → Ctrl+Z/Y」；
  ③ 通关墨框出现、`Enter` 再来一局、`Esc` 回首页；
  ④ 关窗重启后「继续游戏」可用且**六项偏好**保持（严格 / 显示笔记 / 笔记模式 / 候选提示 / 夜墨 / 键位，`~/.sudoku-ink/save.txt`）；
  ⑤ 鼠标点空格 → 悬浮面板贴着该格出现且半透明，**只列该格可填的数字**（键 48dp、1–3 列自适应）→
     点键填数后面板消失、数字落格；
  ⑥ 打开「候选提示」→ **所有空格**出现**半透明灰**候选数字 → 填数后该格与其同行列宫的候选同步刷新；
     有笔记的格子显示笔记而不是候选。

## 6. 贡献与扩展

- 新增功能时，规则改动放 `core`，状态改动放 `state`，表现放 `ui`
  （对照 `.codebuddy/rules/sudoku-dev.md` §3.6 的"常见改动指引"表，避免漏改文件）。
- 新增平台：直接在 `composeApp/build.gradle.kts` 的 `kotlin { }` 增加 target（无第三方库，不再有"变体是否已发布"的前提）
  → 写对应 entrypoint → **补 `SafeArea.kt` 的 actual（安全区，缺了会编译失败）**
  → 过一遍输入差异（`docs/05` §3.3）与屏幕档位（§3.4）；`core` / `state` 应零改动。
- **暂不拆分 Gradle 模块**：单模块已能守住分层约束，拆分收益（强制依赖方向、并行编译）在第二个平台落地前小于成本，
  时机判断见 `docs/05` §2 阶段 C。
- 提交前确保 `core` 与 `state` 不引入任何平台依赖，保持"一份核心、多端复用"。
- 文档义务：改行为必须在同一次改动内更新对应文档（映射见 `docs/04` §0 表）。

## 7. 已知风险

- 构建依赖联网（首次拉取 Compose 依赖体积较大，耗时取决于网络）。
- Android 目标未启用：`compileSdk 37` 的硬约束来自此前那个第三方 UI 库的 aar，**已随该依赖一并移除**；
  本机 android-35/36 即可用，待补的是 AGP / `androidTarget()` / `activity-compose`
  与 `SafeArea` 的 android actual，平台矩阵与启用步骤见 `docs/01` §1、`docs/05` §3.1。
- 打包相关：`packageMsi` 首次运行需联网（WiX 约 99 MB 落到根 `build/wix311`，删掉后重打需重下）；
  DMG 需 macOS 主机；Linux deb 需 Linux 主机（本次仅验证 MSI）。
- **文档漂移**：历史上出现过"文档承诺了窗口尺寸与键盘映射、代码里没有"的偏差；缓解手段是 `docs/04` §9 的维护约定
  + 提交前自检清单（`.codebuddy/rules/sudoku-dev.md` §6）。
- **归档误用**：`archive/` 下的 TS / Rust 实现只是历史资料，与当前 Kotlin 实现不保证语义一致，勿当作参照实现。
