# 开发流程（miuix 版）

> 版本：v1.2（2026-10-06）· 与实现校对（测试 31 项、打包与图标、设置持久化、键盘导航均已落地）
> 关联：`docs/01` 架构设计 · `docs/02` 设计规范 · `docs/04` AI 协作 · `docs/05` 发展规划 · `.codebuddy/rules/sudoku-dev.md` 开发纪律

## 1. 环境准备

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | 17+（本项目用 21） | **启动 Gradle 的 `JAVA_HOME` 必须是 JDK 17–24**；JDK 25 会让 Gradle 8.12 直接失败（报错只有版本号一串，极易误判） |
| Gradle | 8.12（wrapper 已入库） | 直接 `.\gradlew.bat`，无需本机安装 |
| Kotlin | 2.4.0（由 Gradle 插件拉取） | 与 miuix 0.9.2 强绑定 |
| Android SDK | 仅启用 Android 目标时需要 | `D:\env\Android-SDK`（`local.properties` 里的 `sdk.dir`） |
| miuix | 0.9.2 | 经 Gradle 从 Maven 拉取 |

工具链要求：把 **`JAVA_HOME` 指向 JDK 21**（17–24 皆可）——`jvmToolchain(21)` 会复用这个 JVM，
所以仓库里不写死任何本机路径。若 JDK 21 不在 `JAVA_HOME` 或不在标准位置，在**用户级**
`~/.gradle/gradle.properties` 声明（**不要写进仓库**，否则暴露本机路径且对他人无效）：

```properties
# 本机 JDK 21 不在标准位置时：同时固定守护进程 JVM 与工具链解析
org.gradle.java.home=D:/path/to/jdk-21
org.gradle.java.installations.paths=D:/path/to/jdk-21
```

`org.gradle.java.home` 值得单独说明：有了它，**即使 `JAVA_HOME` 被改错（如指向 JDK 25），构建也不会失败**
（已实测：`Daemon JVM: … (from org.gradle.java.home)`，`BUILD SUCCESSFUL`）。Gradle 用 wrapper（8.12）即可，无需本机安装。

```powershell
$env:JAVA_HOME="<你的 JDK 21 路径>"
.\gradlew.bat :composeApp:jvmTest --offline --console=plain
```

## 2. 版本对齐（关键）

`gradle/libs.versions.toml` 当前锁定：

```
kotlin                 = 2.4.0
compose-multiplatform  = 1.11.1
miuix                  = 0.9.2
```

约束关系：**miuix 0.9.2 的 klib 元数据由 Kotlin 2.4.0 编译、且直接依赖 CMP 1.11.1**——
三者必须整体对齐，单独升降级任一项都会导致"Incompatible classes were found in dependencies"。
（历史教训：曾用 Kotlin 2.1.20 / CMP 1.8.0 编译失败，升级后通过。）
miuix 为实验性库，升级时需同步核对组件签名与 Android compileSdk 要求。
Maven Central 上已有 **0.9.3 / 0.9.4**（`latest=0.9.4`），但两者同样要求 `minCompileSdk=37`，
且很可能要求更新的 Kotlin / CMP——**升级不解决 Android 问题**，反而要重新做一次版本对齐核验（已验证：0.9.3/0.9.4 亦为 37）。

## 3. 构建与运行

Gradle wrapper（8.12）已入库，统一使用：

```bash
.\gradlew.bat :composeApp:run                     # 桌面运行
.\gradlew.bat :composeApp:compileKotlinJvm        # 编译
.\gradlew.bat :composeApp:jvmTest --offline       # 单元测试（31 项）
.\gradlew.bat :composeApp:createDistributable     # 自带 JRE 的分发目录（binaries/main/app/SudokuInk）
.\gradlew.bat :composeApp:packageMsi              # Windows 安装包（首次需联网下载 WiX，约 99 MB）
```

打包约定（2026-10-06 实测通过，产物 `SudokuInk-2.0.0.msi` 约 60 MB，产品名 / 制造商 / 图标均正确）：

- `packageName` **必须纯 ASCII、无空格**（jpackage 会把它当产品名、安装目录名与 MSI 标识；旧值 `"数独 Sudoku"` 有失败风险）。
- `description` / `vendor` / `copyright` 在 `composeApp/build.gradle.kts` 的 `nativeDistributions` 里声明。
- 图标：`tools/make-icon.ps1` 生成 `composeApp/icons/sudoku.ico`（16–256 共 7 档）与 `sudoku.png`，
  再由 `windows { iconFile }` / `linux { iconFile }` 接入；**改视觉后重跑一次脚本**即可（不必每次构建都生成）。
  构图按尺寸自适应：≥40px 用 9×9 细线 + 宫线 + 主对角线 5 枚实心墨格，<40px 简化为 3×3 + 中心墨块；
  ≥128px 的网格线带确定性微弯（与 `inkLine` 同一思路）。
  macOS 需要 `.icns`（`iconutil` 仅 macOS 提供），当前 DMG 使用 jpackage 默认图标。

### 3.1 Windows 试运行（三种方式，按"临时 → 正式"排序）

| 方式 | 命令 / 操作 | 适用 | 注意 |
|---|---|---|---|
| ① 开发运行 | `.\gradlew.bat :composeApp:run` | 改代码后立即看效果 | 依赖本机 JDK 21（已由用户级 `~/.gradle/gradle.properties` 固定）；关掉控制台即退出 |
| ② 便携版（推荐日常试玩） | `.\gradlew.bat :composeApp:createDistributable` → 双击 `composeApp\build\compose\binaries\main\app\SudokuInk\SudokuInk.exe` | 不带开发环境体验完整程序 | **自带 JRE**，拷到别的 Windows 机器也能跑；整个 `SudokuInk` 目录一起拷 |
| ③ 安装包 | `.\gradlew.bat :composeApp:packageMsi` → 运行 `composeApp\build\compose\binaries\main\msi\SudokuInk-2.0.0.msi` | 验证安装 / 卸载、开始菜单与图标 | 首次需联网下载 WiX（约 99 MB）；安装需要管理员权限 |

运行期事实（三种方式一致）：

- 存档：`%USERPROFILE%\.sudoku-ink\save.txt`（纯文本，删掉即清空续局；格式见 `docs/01` §5）。
- 窗口：默认 1180×900、最小 940×720；窗口最小化会自动暂停计时。
- 退出：首页「退出游戏」→ 确认，或直接关窗（未完成对局已自动存盘）。
- 纯键盘可走完：首页 `↑↓` + `Enter` → 对局 `1–9` / 方向键 / `Ctrl+Z` → 通关 `Enter` 再来一局。

## 4. 目录约定

- `core/`：纯算法，**禁止** IO / 时钟 / UI / 平台 API。
- `state/`：纯状态机，**禁止** Compose / 平台 API；随机源以参数注入。
- `ui/`：仅此层可调用 miuix / Compose / Canvas。
- 平台入口放在 `androidMain` / `jvmMain`，仅做装配。
- `tools/`：构建期辅助脚本（当前只有 `make-icon.ps1`），**不参与编译**；产物落在 `composeApp/icons/`。
- 仓库根不放截图、日志、构建产物：`build/`、`.gradle/`、`.kotlin/` 均已在 `.gitignore` 中。

## 5. 测试

- **内核单测**：`commonTest/.../core/SudokuTest.kt` —— 唯一解、求解一致性、时长格式、冲突检测、四档难度挖空达标（5 项）。
- **状态机单测**：`commonTest/.../state/GameReducerTest.kt` —— 固定种子覆盖 NewGame / 给定格拒绝 /
  落子与二次按键清除 / 无变化不入撤销栈 / 笔记模式 / 严格模式 / 撤销重做（含提示计数回滚）/ 看答案后撤销重做 /
  方向键跳过给定格 / 填满判胜 / 暂停与停表 / 重置（12 项）。
- **计时与事件单测**：`commonTest/.../state/GameClockTest.kt` —— 注入假时钟，验证"按真实时间而非心跳次数计时"、
  暂停/离开停表、最小化暂停幂等、相同文案逐条送达、重置归零（5 项，不依赖 sleep）。
- **存档单测**：`commonTest/.../state/GameStoreTest.kt` —— v2 往返（对局 + 设置）、无对局只有设置、v1 向后兼容、
  非法输入拒绝、设置跨重启与跨新局保留、重启恢复对局、通关后只留设置、重置保留对局（9 项）。
- **运行方式**：`.\gradlew.bat :composeApp:jvmTest --offline`（当前 **31 项全绿**）。
- **UI 层**：暂无自动化 UI 测试。桌面端验收用**键鼠试玩 + 系统截图**，清单：
  ① 三档窗口（1180×900 双栏 / 800×600 纵向滚动 / 500×1000 手机竖屏）；
  ② 纯键盘走完「↑↓ 选入口 → Enter 进局 → 方向键选格 → 数字填数 → Ctrl+Z/Y」；
  ③ 通关墨框出现、`Enter` 再来一局、`Esc` 回首页；
  ④ 关窗重启后「继续游戏」可用且三项偏好保持（`~/.sudoku-ink/save.txt`）。

## 6. 贡献与扩展

- 新增功能时，规则改动放 `core`，状态改动放 `state`，表现放 `ui`
  （对照 `.codebuddy/rules/sudoku-dev.md` §3.6 的"常见改动指引"表，避免漏改文件）。
- 新增平台：先在 `docs/05` §3.1 确认 miuix 有该平台变体 → 在 `composeApp/build.gradle.kts` 的 `kotlin { }`
  增加 target → 写对应 entrypoint → 过一遍输入差异（`docs/05` §3.3）与屏幕档位（§3.4）；`core` / `state` 应零改动。
- **暂不拆分 Gradle 模块**：单模块已能守住分层约束，拆分收益（强制依赖方向、并行编译）在第二个平台落地前小于成本，
  时机判断见 `docs/05` §2 阶段 C。
- 提交前确保 `core` 与 `state` 不引入任何平台依赖，保持"一份核心、多端复用"。
- 文档义务：改行为必须在同一次改动内更新对应文档（映射见 `docs/04` §0 表）。

## 7. 已知风险

- miuix 实验性：API 可能变更，升级需回归 UI 层；且 0.9.2 强制 Kotlin 2.4.0 / CMP 1.11.1 /（Android 侧）compileSdk 37。
- 构建依赖联网（首次拉取 Compose/miuix 体积较大，耗时取决于网络）。
- Android 目标未启用：miuix 的 aar 要求 `compileSdk 37`（0.9.2/0.9.3/0.9.4 相同），本机 SDK 只装到 android-36。
  `platforms;android-37` 与 `build-tools;37.0.0` 现已发布，装好 SDK 并补上 AGP / `androidTarget()` 即可启用，
  平台矩阵与启用步骤见 `docs/01` §1、`docs/05` §3.1。
- 打包相关：`packageMsi` 首次运行需联网（WiX 约 99 MB 落到根 `build/wix311`，删掉后重打需重下）；
  DMG 需 macOS 主机；Linux deb 需 Linux 主机（本次仅验证 MSI）。
- **文档漂移**：历史上出现过"文档承诺了窗口尺寸与键盘映射、代码里没有"的偏差；缓解手段是 `docs/04` §9 的维护约定
  + 提交前自检清单（`.codebuddy/rules/sudoku-dev.md` §6）。
- **归档误用**：`archive/` 下的 TS / Rust 实现只是历史资料，与当前 Kotlin 实现不保证语义一致，勿当作参照实现。
