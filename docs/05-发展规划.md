## 2. 架构演进路线

### 阶段 A（当前）：单目标 + 纯状态机

`输入 → GameAction → GameReducer.reduce → GameState → Compose 重组`，副作用（生成题目、Snackbar、计时）由 UI 层承担。

- **优点**：状态可回放、可单测（`GameReducerTest` 已有 13 项用例）、无框架依赖、跨端零改造成本。
- **局限**：副作用散在 UI；派生状态每次重算；状态里混了"事件"（`message`）。

### 阶段 B（下一阶段，收益最高）：把状态机做"干净"

| 改动 | 做法 | 收益 | 代价 |
|---|---|---|---|
| ✅ 事件通道（已完成，见 §5.1 #1） | `GameState.message` → `Reduction(state, message)` + `Channel<String>`，UI 侧 collect 后 Snackbar | 事件不再受状态等值比较影响；相同文案可连续提示 | — |
| 派生状态 | 冲突 / 进度 / legalMask 用 `derivedStateOf` 或在 reducer 内算好存字段 | 消除每秒重算；Canvas 参数稳定后减少重绘 | 状态字段变多，需明确"哪个是真相、哪个是派生" |
| 时钟注入 | 心跳只做"到点校对"，用 `TimeSource.Monotonic` 计算真实耗时；`Clock` 作为参数注入 reducer | 计时不再漂移；可测（注入假时钟） | reducer 签名或 Action 载荷变化，需同步 `docs/01` |
| 出题达标 | `generate` 重试至达到目标空格，或返回实际空格数并展示 | 难度名与实际一致 | 生成耗时上界需设限（实测单次 1–4 ms，重试 3 次仍在 15 ms 内） |

### 阶段 C（按需）：Gradle 模块拆分

当前是"单模块多源集"（`composeApp` 内含 commonMain / jvmMain / androidMain）。拆分为
`:core` / `:state` / `:ui` / `:platform-jvm` / `:platform-android` …的收益是**强制依赖方向**与并行编译。

- **建议：在启用第二个平台之前不要拆。** 理由：单模块已能把 core/state 的零依赖约束守住（靠评审 + 规则文件），
  拆分带来的版本对齐、增量编译配置、IDE 索引成本短期内大于收益；一旦 `ui` 需要给 iOS/Web 复用并出现编译时间问题，再拆。
- 若拆，顺序：先抽 `:core`（无任何依赖）→ 再抽 `:state` → `:ui` 与入口留在 `:app`。

### 阶段 D（可选）：数据与同步

持久化 → 战绩 → 每日题 → 云同步，会引入新的架构层：

```
ui ── Action ──▶ reducer ──▶ (State, Effect) ──▶ Effect 执行器（存储 / 网络） ──▶ 新 Action
                                  ▲
                            新增：Repository（战绩 / 存档 / 题目源）
```

关键纪律：**Repository 只能被 Effect 执行器调用，不能进 reducer**（否则纯函数与可回放性立刻丢失）。
引入时机：当"对局恢复 + 战绩统计"成为必须功能（见 M3）时再上，不要提前。

## 3. 跨平台适配策略

### 3.1 平台矩阵（2026-10-07 复核）

| 平台 | 本机（Windows）能否构建 | 需要补的工作 | 优先级 |
|---|---|---|---|
| Desktop / JVM | ✅ 已跑通 | ✅ 打包标识已安全化（ASCII `packageName` + `vendor` / `description` / 图标），`packageMsi` 实测产出安装包（见 §5.2 #10） | — |
| Android | ⚠️ 装 SDK 后可以 | AGP 插件 + `androidTarget()` + `activity-compose` 依赖 + 图标资源 + **`SafeArea.kt` 的 android actual**（安全区）。`compileSdk 37` 的硬约束来自此前那个第三方 UI 库的 aar，**已随该依赖移除**，本机 android-35/36 即可用 | **P0** |
| Web（wasm-js / js） | ✅ 可以（无需 Mac） | 新增 `wasmJs { browser() }` target + Web 入口（`ComposeViewport`）+ 资源与体积评估（含 24.7MB 字体） | P1 |
| iOS | ❌ 需 macOS 主机 | target + `MainViewController` 入口 + `SafeArea` 的 ios actual | P2 |
| macOS 桌面 | ❌ 需 macOS 主机 | `macosArm64()` target + 打包（dmg） | P2 |

> 结论：**缺的只是项目侧的 target 声明与入口**（以及 `SafeArea` 的 actual）。core/state 已零平台 API，
> 因此新增平台不改业务代码——这是本工程最值得保持的设计。
> 新增平台**不再有"库是否发布了该平台变体"这一前提**（此前 iOS 曾受限于第三方库的变体缺失）。

### 3.2 分层复用策略

| 层 | 跨端复用度 | 说明 |
|---|---|---|
| `core/` | 100% | 纯算法；新增平台**零改动** |
| `state/` | 100% | 纯 reducer；随机源注入已就绪，时钟注入是阶段 B 的补课 |
| `ui/` | ~100% | 全自绘组件，跨端天然一致；差异集中在"屏幕尺寸 / 输入方式"（见 3.3、3.4）与安全区 actual |
| entrypoints | 0%（按平台各写） | 只做装配：窗口 / Activity / 视口 |
| 平台能力 | expect/actual | 候选清单见 3.5 |

### 3.3 输入方式差异（同一 UI 的三套输入）

| 输入 | 现状 | 待补 |
|---|---|---|
| 触摸 | 点格选中 + 点数字键 | 长按擦除、拖动连续填数、触感反馈 |
| 鼠标 | 点击、滚轮（未用）、右键（未用） | 悬停高亮、右键擦除/取消笔记 |
| 键盘 | ✅ 全量映射（含方向键跳给定格） | 手柄 / Tab 序焦点环（电视机、折叠屏外设） |

### 3.4 屏幕与窗口适配

- 已实现：宽 ≥ 720dp 且宽 > 高 → 双栏；否则纵向滚动。
- 待验证档位（列入每次 UI 改动的验收清单）：1180×900（桌面默认）、800×600（小窗）、500×1000（手机竖屏）、
  平板横屏（如 1024×768）、折叠屏展开态的极端宽高比。
- 原则：**棋盘永远是正方形且优先保证"数字键盘与棋盘同屏可见"**；空间不足时宁可滚动也不要压缩键盘。

### 3.5 平台能力抽象（需要 `expect/actual` 的候选）

| 能力 | 用途 | 抽象形式 |
|---|---|---|
| 持久化 | 存档 / 战绩 / 设置 | `expect class Storage { fun read(key): String?; fun write(key, value) }` |
| 生命周期 | 切后台自动暂停、最小化停表 | `expect fun observeAppActive(): Flow<Boolean>` |
| 音效 / 触感 | 落子反馈（移动端尤甚） | `expect fun feedback(kind)` |
| 分享 | 每日题 / 战绩分享 | `expect fun share(text)` |
| 系统主题 | Android Monet 取色、macOS 外观 | 已由 `isSystemInDarkTheme()` 覆盖大部分；Monet 走 `ThemeController` |

### 3.6 跨平台风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 移动端安全区（`SafeArea`）目前只有 jvm actual（恒 0） | 新增 Android / iOS 时可能漏掉刘海与导航栏 | 做成 `expect/actual`：**缺 actual 会编译失败**，不会静默漏掉（见 `docs/02` §3.2） |
| Web 端字体体积（24.7MB 随包） | 首屏下载过大 | 启用 Web 前先做子集化；子集属"修改版本"，需按 OFL 第 3 条处理保留字体名 |
| iOS / macOS 需 Mac 主机 | 本机无法验证 | 先做 Web（可本机验证），iOS 留到有 Mac 环境 |
| Web 端 Canvas + 文本测量性能 | 81 格重绘在低端设备可能掉帧 | 复用现有跨帧文本缓存；必要时按"行"分块重绘或改 `drawIntoCanvas` |
| 高 DPI / 大字体 | 曾出现字号溢出（已修：`toSp()`） | 新增绘制一律用 dp / `toSp()`，禁止裸像素 |

## 5.11 对局页重构：顶栏 + 浮动操作条 + 双主题（第十二轮，2026-10-07）

**背景**：上一轮把可视层的问题修完了，本轮解决的是**结构**——
此前对局页的"状态行 + 棋盘 + 控制栏"里，控制栏底部塞着 6 个按钮（撤销 / 重做 / 提示 / 暂停 / 重置 / 菜单），
棋盘四周到处是控件，与"手写纸 · 简约油墨"的安静感冲突。同时补齐了 Tier 2 的「夜墨」主题。

### 5.11.1 布局重构（需求 #2 #3 #4 #6）

| # | 项 | 落地 |
|---|---|---|
| 2 | 撤销 / 重做改为**浮动操作条** | 棋盘上**下各留一条 48dp 专用槽**，条只在槽里出现（**绝压不到题面**）；鼠标进棋盘上方 35% → 贴上方，进下方 65% → 贴下方，中间 30% 是**滞回死区**。滞回是刻意的：按中线一刀切的话，鼠标停中线附近微动就会让条来回跳，指着的"撤销"会变成"重做" |
| 3 | 控制开关统一到顶部 | 新增 `GameTopBar`（56dp）：左「返回菜单」· 中状态读数 · 右「提示 / 暂停 / 重置 / 明暗切换」；**控制栏里的 6 个按钮全部移除**，面板只留偏好开关 |

**"强制正方形"不是审美问题**：`BoardCanvas` 按 `min(宽, 高)` 画网格，而语义层按"父容器 1/9"铺开

**读屏报出的格子就会与眼睛看到的格子错位**。这一条是本轮实现里真踩到的。

### 5.11.2 双主题（需求 #5）

| 项 | 落地 |
|---|---|

### 5.11.3 输入冗余检查（需求 #1）

结论：桌面鼠标的三个入口（悬浮面板 / 常驻键盘 / 物理键盘）**不是重复，删任何一个都会留功能缺口**。
- 悬浮面板只列合法候选 → 擦除与"记不可能的数字"它做不到；
- 常驻键盘有剩余计数与擦除、笔记模式要能记 1–9 全部 → 不能被面板替代。

查出的两处**真重复**已修：① 同一时刻两个键盘按同一份 `legalMask` 过滤（保留了过滤这个有用的护栏，
但把两份重复计算合并为按盘面缓存的一次）；② 面板关不掉的死角（此前只能靠 `Esc` 或点棋盘外关闭）→ 补上"再点一次同一格收起"。

**刻意不做**"悬浮面板出现时自动隐藏常驻键盘"：会让擦除 / 记任意数字在鼠标路径下无处可去，
且显隐会引起布局跳动——**布局跳动比功能重复更伤体验**。

### 5.11.4 验证

- 测试 **80 → 92 项全绿**（新增 `InkThemeTest` 4 对比度底线、`FloatingBarPolicyTest` 6 换边滞回、
  `GameStoreTest` +1 缺行兼容、`FloatingPadPolicyTest` +1 开合切换）；
- 实机冒烟**新增两条流**：`theme`（夜墨开局 → 点右上角切回浅色）、`bar`（鼠标移到棋盘上/下半部，
  两张截图验证浮动条真的换边）；
- 截图判定同步改为接受两套主题（原判定"整屏偏白"，夜墨会被误判成锁屏）。

### 5.11.5 本轮踩到的三个坑（值得记住）

1. **`pointerInput` 里读 `size.height` 会拿到 0**——协程在首次布局前启动、且只在 key 变化时重启，
   于是会一直拿着 0，表现为"浮动条永远不动"。**单测抓不到**，只有真机把鼠标移进棋盘才暴露；
   改为 `onSizeChanged` 记账后在事件循环里读。
2. **`InkPanel` 默认 `fillMaxWidth`**——浮动条只有两个按钮，撑满整宽会变成横贯棋盘的空白带。
   给它加了 `fillWidth = false`。
3. **劫持的指针事件必须 `clickable` 到**——语义层若先吃掉 press/release，棋盘的 `pointerInput` 就拿不到。

## 5.12 棋盘四周清空 + 数字可辨 + 图标重绘（第十三轮，2026-10-07）

**背景**：第十二轮把结构改成了三段式，但棋盘**右侧还立着一整块 360dp 控制栏**（数字键盘 + 开关面板），
填一个数要左右横扫一次；同时"哪些数字是自己填的"只靠墨色深浅，浅色纸上仍会看混。

### 5.12.1 棋盘四周清空（需求 #1）

- **右侧控制栏整块移除**：功能区压到棋盘**下方**，只留两行——第一行 1–9 **横向** + 擦除，
  第二行四项偏好**一行**排开。开关不竖排的理由：竖排要占 ~170dp，棋盘就得再矮 130dp，
  而它们是"设一次就不管"的开关，不值得拿棋盘尺寸去换（横排后整块功能区只有 102dp）。
- **数字键改为 1–9 横向等分 + 擦除固定宽**：擦除是两个汉字，等分会被压得比数字键还窄，读起来就不像"擦除"了。
- **断点一并删掉**：原先"宽屏双栏 / 窄屏滚动"两套形态，现在只有一条纵列，靠
  `boardSide = min(可用宽 − 留白, 可用高 − 预留)` 自适应——少一套形态就少一套要各自验收的布局。
  `Sizes.WideBreakpoint` / `ControlPanel` 两个令牌因此成了死代码，一并清掉。

### 5.12.2 给定数字 vs 填入数字（需求 #2）

三重信号，任取其一都分得开：**墨色**（一墨 / 二墨）+ **字形**（数字族 Nunito 印刷体 / 正文族霞鹜文楷手写体）
+ **读屏文案**（"给定 5" / "填入 9"）。读作"题面是印的，你填的是写的"。

**为什么用字形而不是字重**：包里只打了一份 Nunito（Regular），请求 `FontWeight.Bold`
会**退回系统字体**——那不是"加粗的给定数字"，而是"给定数字换了一副字形"，看起来更像 bug。

### 5.12.3 点棋盘外空白 → 清临时标记（需求 #3）

新增 `GameAction.Deselect`：只把 `selected` 置空（选中框、同行列宫高亮、同值高亮都从它派生，一并消失）。
**盘面 / 笔记 / 冲突 / 计时 / 提示次数 / 撤销栈一律不动**，且**不写盘**（与 `Select` 同类：存档里没有这一项）。
冲突排线也**不清**——那是对局数据，清掉等于骗玩家。

实现在内容**下面**垫一层 `matchParentSize` 的可点空白：命中测试对**兄弟**是命中即剪枝，
点到棋盘 / 按键 / 开关时命中的是上层节点，空白层根本不进事件链——不靠事件消费的博弈。

### 5.12.4 图标重绘 + 悬停功能名（需求 #4）

- **按骨架差异设计**而不是细节差异：返回（唯一水平的箭头）/ 撤销·重做（互为镜像的半圈弧）/
  重置（接近整圈的弧）/ 暂停·继续（两竖杠 vs 三角）/ 提示（灯泡，不用"!"——太容易被读成警告）/ 明暗（太阳 · 月牙）。
- **悬停浮出功能名**：一张小纸片贴在按钮正下方，移开淡出。默认取 `contentDescription`（它本来就是人话功能名，
  另造字段只会让两者走偏）；需要更短时才显式传（读屏念"切换到夜墨模式"，浮出来只写"夜墨模式"）。

### 5.12.5 验证

- 测试 **92 → 96 项全绿**（新增 `GameScreenUiTest` 3 + `GameReducerTest` +1 取消选格）；
- 实机冒烟新增 `ux` 流：悬停提示、点格子高亮、**点空白高亮全消**、给定 vs 填入对比（共 16 张截图，两套主题）。

### 5.12.6 本轮踩到的三个坑（值得记住）

1. **语义网格与绘制网格错位**（无障碍真缺陷，已修）：`BoardCellSemantics` 的 9×9 用
   `fillMaxHeight(1f/9f)` 铺开，而 Column / Row 给子项的是**"剩余"**空间——于是逐行逐列缩水，
   9 行只铺满约 **65%**，后果是"读屏念第 5 行第 5 列、点下去选中第 4 行第 4 列"。
   修法：`weight(1f)` 等分。**这条缺陷长期没被发现，是因为那条用例只点了"第 2 行第 2 列"——
   偏差越往后越大，前两三行还不到一格，正好蒙对**；用例已改为拿最后一格当哨兵。
2. **悬停判据不能只看 `PointerEventType.Move`**：指针**刚进入**容器时 Compose 报的是 `Enter`、之后才是 `Move`，
   只认 `Move` 会漏掉"一步跨进棋盘"（实机 `SetCursorPos` 正是这种），表现为"鼠标明明在棋盘上半部，条却不动"。
   改用 `change.pressed == false`（未按下 = 悬停），顺带排除手指拖动。
3. **提示片会被按钮自己的 36dp 宽度截断**：不是被窗口切掉，而是父容器约束太紧，文字被截成"夜…"。
   要用 `wrapContentSize(align, unbounded = true)`，并按 `tooltipAlignment` 决定往哪边长（贴边按钮必须给方向）。

## 5.13 题面数字加「字框」标识符（第十四轮，2026-10-07）

**背景**：第十三轮给两类数字做了"墨色 + 字形"区分，但反馈是**仍不够**——这两条都属**中心视觉**，
必须逐格看清、逐个数字比对才判断得出来；玩家想要的是"一眼扫过就知道哪些是我填的"。

**做法**：给定数字各占一个手绘小框（边长 0.74 格、线宽 `Thin`、`Ink.Alpha.TypeBox`），
填入数字不带框——"一屏之内多数数字带框、少数不带框"，在余光里就成立。

### 5.13.1 一条硬规则：常驻标识走形状，临时状态走亮度

先说被否掉的方案：**给题面格铺整格压印底**。它一眼可见，但**亮度通道已被临时状态占满**
（选中 `WashStrong` / 同值 `Wash` / 同行列宫一档），常驻标识挤进同一条通道后两层信息互相糊掉——
选中一行时"哪几格是题面"与"哪几格在同一行"分不出轻重（截图实测如此）。而且它**没法取值**：
取 `0.07` 就等于 `Wash`，同值高亮的空格会看起来像题面格；取更重则盖住数字本身。

**定案**：亮度通道只归临时状态（wash，用完即走）；常驻标识走**形状**通道（框是线，不占亮度）。
两条通道互不干扰，选中态的层级因此完全清晰。

### 5.13.2 字框的两条数值约束

| 约束 | 实测 | 理由 |
|---|---|---|
| 下界 ≥ 1.5:1 | 纸墨 **2.30:1** / 夜墨 **2.51:1** | 太淡等于没装——"只调字形 / 墨色"那一版的失败点正在这里 |
| 上界 ≤ 3.5:1 且与数字差一个量级 | 题面数字 17.4 / 14.4 | 它只是标识符，不能盖过数字，也不能和宫线混成表格 |

**两套主题各取一档**：同样浓度的线在深底上更"亮"，沿用 `0.42` 会让夜墨达到 **3.6:1**（逼近正文门槛）；
`Ink.Alpha.TypeBox` 因此写成 getter（纸墨 `0.42` / 夜墨 `0.30`），两套落回同一档观感。
`InkThemeTest` 新增 1 项把上下限钉住——**人的手感会随显示器漂移，数字不会**。

### 5.13.3 验证

- 测试 **96 → 97 项全绿**（`InkThemeTest` +1 字框可见度底线）；
- 实机冒烟复跑全部六条流（16 张截图）：纸墨下 44 个题面数字带框、玩家填入的"9"无框更淡更斜；
  夜墨下框同样清楚，且**选中 / 同值高亮的层级完全清晰**（这正是通道分离要保的东西）。

## 5.14 键盘光标：定位 / 导航 / 自动跳转（第十五轮，2026-10-07）

**背景**：对局页此前只有"点格子 + 按数字"，键盘玩家每填一格都要按方向键挪一次，
方向键还会停在题面格上（按数字没反应）。本轮把**光标**当一等公民补齐：初始位置、方向键导航、
填字后自动跳转，三者都由 `core/CellCursor.kt` 的纯函数决定（可单测、可回放）。

### 5.14.1 方向键：空格优先，但不许"回不去"

| 规则 | 为什么 |
|---|---|
| 只在本行 / 本列内环绕 | 按 ← 跳到上一行会让人立刻失去方向感 |
| **停在第一个空格** | 光标的意义就是"下一个要填的格子" |
| 题面格一律跳过 | 改不动，停在上面只表现为"键盘失灵" |
| **该行 / 列没有空格时退到"可编辑格"** | 只认空格的话，某行一填满，键盘玩家就**再也回不到自己填过的格子上去改它**——这是"只在空格间跳"最容易漏的漏洞 |
| 没有选中格时从第一个空格起算 | 否则"点棋盘外的空白"之后再按方向键毫无反应 |

### 5.14.2 自动跳转：选「九宫格优先」（需求里给了两个候选）

| | (a) 横向优先（读序） | **(b) 九宫格优先**（采用） |
|---|---|---|
| 宫内空格按读序排列时 | 逐格落在宫内 | **与 (a) 落点完全相同** |
| 宫里还有"读序更靠前"的空格 | 离开本宫，玩家自己回头补 | **回头把本宫填完** |
| 本宫已填满 | 走读序 | 退回读序 |

三条理由：① **宫是数独的最小推导单元**——填完一格，玩家下一步最常想的是"这个宫还差哪几个"；
② 最常见情形下它与横向优先**逐格相同**，不会让习惯横向推进的玩家吃亏；
③ **方向键与策略解耦**，按行 / 按列扫的玩家仍可用方向键精确控制。

②③ 两条不是感觉，是 `CellCursorTest` 里的断言（`afterFillAgreesWithReadingOrder…` /
`afterFillKeepsTheCursorInsideTheCurrentBox`）——**策略选择本身也有验收标准**。

另外三条边界：**只对物理键盘生效**（鼠标玩家自己点下一格更自然）、
**只有"真的填进一个数字"才跳**（擦除 / 笔记 / 再按一次取消都不跳）、
**盘面已满则不动**（通常意味着刚通关）。

### 5.14.3 视觉反馈：光标落纸（动效第五档）

换格瞬间在格子上洇一层淡墨随即退去（`Motion.CursorLandMs` 200ms，减少动效时不做）。
九宫格优先**会往回跳**，没有这一下反馈，眼睛会一时找不到光标去了哪儿。
两个刻意的选择：**只叠淡墨、不加新形状**（格内已有选中框 / 题面字框 / 候选小字 / 冲突排线）；
**不让选中框本身闪烁**——按住方向键自动重复时，主框忽明忽暗比没有反馈更糟。

### 5.14.4 验证

- 测试 **97 → 117 项全绿**：`CellCursorTest` 13（含两策略对比）+ `GameReducerTest` +6
  （初始定位 / 跳转 / 擦除与笔记不跳 / 屏幕键盘不跳 / 无选中也能按方向键）+ `MotionPolicyTest` +1；
- 实机冒烟新增 `keys` 流：**5 张截图逐步核对**开局定位 → 方向键 → 填数逐格跳转 →
  宫满回退（填完宫 8 的最后一格后，光标跳回宫 7 里的 77）；
- 修掉冒烟脚本里两个真 bug：方向键漏传扩展位（表现为"按了没反应"）、`Left` / `Right` 虚拟键码写反。

## 6. 明确不做（避免范围蔓延）

- 不引入 DI 框架（Koin / Hilt）、导航框架（Navigation）、ORM：当前规模用不上，只会增加跨端适配面。
- 不为"看起来跨平台"而提前拆模块或提前写 `expect/actual`（阶段 C/D 的时机判断见上文）。
- 不引入任何第三方 UI 组件库（含 Material3）：自绘墨线是唯一视觉来源，否则风格与依赖都会分裂。
- 不做"必须先联网"的核心玩法：数独的完整玩法必须离线可用。
