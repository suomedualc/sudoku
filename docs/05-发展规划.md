# 发展规划（miuix 版）

> 版本：v1.0（2026-10-06）
> 定位：在**保持 core / state 可移植**这一前提下，回答"下一步做什么、为什么这么做、做到什么程度算完成"。
> 约束：本文只写方向与验收标准，可执行的纪律在 `.codebuddy/rules/sudoku-dev.md`；实现细节在 `docs/01`–`docs/03`。

## 1. 现状快照（事实基线，2026-10-06）

| 维度 | 现状 |
|---|---|
| 目标平台 | 仅 `jvm()`（Windows 实测编译 / 测试 / 运行通过；窗口 1180×900；首页→难度→对局→冲突→重启续局 全链路截图验收） |
| 架构 | `core`（零平台依赖）→ `state`（纯 reducer + 存档端口）→ `ui`（唯一接触 Compose/miuix）→ entrypoints |
| 视觉 | **手写纸 · 简约油墨**：只有纸墨两色、自绘墨线控件（`InkWidgets`）、系统手写体；miuix 只保留主题/骨架/提示（见 `docs/02`） |
| 代码规模 | 21 个 Kotlin 源文件 + 1 个 Manifest；commonMain 为主要载体 |
| 测试 | 22 项全绿：`SudokuTest` 4（内核）+ `GameReducerTest` 12（状态机）+ `GameStoreTest` 6（存档） |
| 已实现玩法 | 出题（唯一解）、难度 4 档、填数/擦除、笔记、墨线冲突标记、严格模式、撤销重做（上限 300）、提示、重置、暂停遮题、计时 |
| 首页 | **只有三个入口**：开始游戏（难度面板）/ 继续游戏（无存档时置灰说明）/ 退出游戏（二次确认）；无对弈、联网、社交 |
| 持久化 | 对局自动存盘（桌面 `~/.sudoku-ink/save.txt`，纯文本 `SaveCodec`），重启可续局；通关/结算清档 |
| 交互 | 鼠标 / 触摸点选 + 桌面键盘全量映射（1–9、0/Delete、方向键跳给定格、N/H/P/Esc、Ctrl+Z/Y） |
| 布局 | 宽屏双栏（棋盘顶部对齐 + 为提示条预留 64dp）/ 窄屏纵向滚动；四档窗口已列入验收清单 |
| 依赖 | Kotlin 2.4.0 · CMP 1.11.1 · miuix 0.9.2（强绑定，见 `docs/03` §2） |

**已知缺口（按影响排序）**

1. 一次性提示仍是 `GameState.message` + `ConsumeMessage`，相同文案会被吞掉（事件混入状态）。
2. 计时是 `delay(1000)` 累加：长局有漂移；窗口最小化 / 切后台仍在走表。
3. `viewModel.conflicts / progress / legalMask` 为普通 getter，每秒 Tick 触发重组时重算重分配。
4. 出题在"大师 56 空"档实测有 3/25 次挖不满（实测空格 53–55），难度名与实际不符。
5. 存档只保存对局，不保存玩法开关（`strictMode / showNotes / noteMode` 每次重开回到默认）。
6. 无障碍只到"整盘语义"，缺逐格语义与朗读；首页三入口暂无键盘 ↑↓ 选择。
7. Android 未启用（缺 `compileSdk 37` 的 SDK 包）；iOS/Web 未声明 target。
8. 统计/记录页已随"首页三入口"改版移除（原为占位页，不可达），战绩需求顺延到 M3 并按墨线风格重新设计。

## 2. 架构演进路线

### 阶段 A（当前）：单目标 + 纯状态机

`输入 → GameAction → GameReducer.reduce → GameState → Compose 重组`，副作用（生成题目、Snackbar、计时）由 UI 层承担。

- **优点**：状态可回放、可单测（已有 12 项用例）、无框架依赖、跨端零改造成本。
- **局限**：副作用散在 UI；派生状态每次重算；状态里混了"事件"（`message`）。

### 阶段 B（下一阶段，收益最高）：把状态机做"干净"

| 改动 | 做法 | 收益 | 代价 |
|---|---|---|---|
| 事件通道 | `GameState.message` → `Channel<UiMessage>(BUFFERED)` / `SharedFlow`，UI 侧 collect 后 Snackbar | 事件不再受状态等值比较影响；相同文案可连续提示 | 需要注入一个作用域（`GameViewModel` 持有 Channel） |
| 派生状态 | 冲突 / 进度 / legalMask 用 `derivedStateOf` 或在 reducer 内算好存字段 | 消除每秒重算；Canvas 参数稳定后减少重绘 | 状态字段变多，需明确"哪个是真相、哪个是派生" |
| 时钟注入 | 心跳只做"到点校对"，用 `TimeSource.Monotonic` 计算真实耗时；`Clock` 作为参数注入 reducer | 计时不再漂移；可测（注入假时钟） | reducer 签名或 Action 载荷变化，需同步 `docs/01` |
| 出题达标 | `generate` 重试至达到目标空格，或返回实际空格数并展示 | 难度名与实际一致 | 生成耗时上界需设限（实测单次 1–4 ms，重试 3 次仍在 15 ms 内） |

### 阶段 C（按需）：Gradle 模块拆分

当前是"单模块多源集"（`composeApp` 内含 commonMain / jvmMain / androidMain）。拆分为
`:core` / `:state` / `:ui` / `:platform-jvm` / `:platform-android` …的收益是**强制依赖方向**与并行编译。

- **建议：在启用第二个平台之前不要拆。** 理由：单模块已能把 core/state 的零依赖约束守住（靠评审 + 规则文件），
  拆分带来的版本对齐、增量编译配置、IDE 索引成本短期内大于收益；一旦 `ui` 需要给 iOS/Web 复用并出现编译时间问题，再拆。
- 若拆，顺序：先抽 `:core`（无任何依赖）→ 再抽 `:state` → `:ui` 与入口留在 `:app`。

### 阶段 D（可选）：数据与同步

持久化 → 战绩 → 每日题 → 云同步，会引入新的架构层：

```
ui ── Action ──▶ reducer ──▶ (State, Effect) ──▶ Effect 执行器（存储 / 网络） ──▶ 新 Action
                                  ▲
                            新增：Repository（战绩 / 存档 / 题目源）
```

关键纪律：**Repository 只能被 Effect 执行器调用，不能进 reducer**（否则纯函数与可回放性立刻丢失）。
引入时机：当"对局恢复 + 战绩统计"成为必须功能（见 M3）时再上，不要提前。

## 3. 跨平台适配策略

### 3.1 平台矩阵（基于 miuix 0.9.2 在 Maven Central 上的**实测**变体）

| 平台 | miuix 变体 | 本机（Windows）能否构建 | 需要补的工作 | 优先级 |
|---|---|---|---|---|
| Desktop / JVM | `-desktop` | ✅ 已跑通 | 打包标识修整（ASCII packageName、vendor/description/图标） | — |
| Android | `-android`（要求 `compileSdk 37`） | ⚠️ 装 SDK 后可以 | `sdkmanager "platforms;android-37"`、AGP + `androidTarget()`、`activity-compose` 依赖、图标 | **P0** |
| Web（wasm-js / js） | `-wasm-js`、`-js` | ✅ 可以（无需 Mac） | 新增 `wasmJs { browser() }` target + Web 入口（`ComposeViewport`）+ 资源与体积评估 | P1 |
| iOS | `-iosarm64`、`-iossimulatorarm64` | ❌ 需 macOS 主机 | target + `MainViewController` 入口；注意**无 `miuix-ui-iosx64`**（Intel Mac 模拟器不支持） | P2 |
| macOS 桌面 | `-macosarm64`、`-macosx64` | ❌ 需 macOS 主机 | `macosArm64()` target + 打包（dmg） | P2 |

> 结论：**库的跨平台能力齐备，缺的只是项目侧的 target 声明与入口**。core/state 已零平台 API，
> 因此新增平台不改业务代码——这是本工程最值得保持的设计。

### 3.2 分层复用策略

| 层 | 跨端复用度 | 说明 |
|---|---|---|
| `core/` | 100% | 纯算法；新增平台**零改动** |
| `state/` | 100% | 纯 reducer；随机源注入已就绪，时钟注入是阶段 B 的补课 |
| `ui/` | ~100% | miuix 全平台同一套组件；差异集中在"屏幕尺寸 / 输入方式"（见 3.3、3.4） |
| entrypoints | 0%（按平台各写） | 只做装配：窗口 / Activity / 视口 |
| 平台能力 | expect/actual | 候选清单见 3.5 |

### 3.3 输入方式差异（同一 UI 的三套输入）

| 输入 | 现状 | 待补 |
|---|---|---|
| 触摸 | 点格选中 + 点数字键 | 长按擦除、拖动连续填数、触感反馈 |
| 鼠标 | 点击、滚轮（未用）、右键（未用） | 悬停高亮、右键擦除/取消笔记 |
| 键盘 | ✅ 全量映射（含方向键跳给定格） | 手柄 / Tab 序焦点环（电视机、折叠屏外设） |

### 3.4 屏幕与窗口适配

- 已实现：宽 ≥ 720dp 且宽 > 高 → 双栏；否则纵向滚动。
- 待验证档位（列入每次 UI 改动的验收清单）：1180×900（桌面默认）、800×600（小窗）、500×1000（手机竖屏）、
  平板横屏（如 1024×768）、折叠屏展开态的极端宽高比。
- 原则：**棋盘永远是正方形且优先保证"数字键盘与棋盘同屏可见"**；空间不足时宁可滚动也不要压缩键盘。

### 3.5 平台能力抽象（需要 `expect/actual` 的候选）

| 能力 | 用途 | 抽象形式 |
|---|---|---|
| 持久化 | 存档 / 战绩 / 设置 | `expect class Storage { fun read(key): String?; fun write(key, value) }` |
| 生命周期 | 切后台自动暂停、最小化停表 | `expect fun observeAppActive(): Flow<Boolean>` |
| 音效 / 触感 | 落子反馈（移动端尤甚） | `expect fun feedback(kind)` |
| 分享 | 每日题 / 战绩分享 | `expect fun share(text)` |
| 系统主题 | Android Monet 取色、macOS 外观 | 已由 `isSystemInDarkTheme()` 覆盖大部分；Monet 走 `ThemeController` |

### 3.6 跨平台风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| miuix 标注 experimental，0.9.3/0.9.4 已发布 | 升级可能改签名 | 锁版本 + 升级前跑"UI 回归清单"（见 `docs/03` §5） |
| Android 要求 `compileSdk 37` | 无法降级 SDK | 升级 AGP 与 SDK；或等 miuix 放宽（0.9.3/0.9.4 仍为 37，已核实） |
| iOS / macOS 需 Mac 主机 | 本机无法验证 | 先做 Web（可本机验证），iOS 留到有 Mac 环境 |
| Web 端 Canvas + 文本测量性能 | 81 格重绘在低端设备可能掉帧 | 复用现有跨帧文本缓存；必要时按"行"分块重绘或改 `drawIntoCanvas` |
| 高 DPI / 大字体 | 曾出现字号溢出（已修：`toSp()`） | 新增绘制一律用 dp / `toSp()`，禁止裸像素 |

## 4. 功能扩展可能性（按性价比分层）

### Tier 1 —— 低成本、直接改善体验（建议紧随阶段 B 落地）

| 功能 | 价值 | 依赖 | 验收标准 |
|---|---|---|---|
| 数字键剩余计数（每个数字还差几个） | 减少重复扫描，是数独 App 的标配 | 无（reducer 派生） | 每个数字键显示剩余数，填满后置灰 |
| 撤销 / 重做按钮可用态 | 消除"点了没反应"的困惑 | 无 | `undoStack/redoStack` 为空时按钮禁用 |
| 自动记笔记（auto-notes） | 新手友好 | reducer 新 Action | 开启后落子自动清同行列宫候选 |
| 通关墨框（对话框）+ "再来一局" | 现有反馈只有 Snackbar，偏弱 | 复用现成的 `InkOverlay`（无需引入 miuix 对话框） | 通关弹出墨框，含用时 / 提示次数 / 再来一局 |
| ~~对局自动保存与恢复~~ | **✅ 已在 v2.0 完成**（`GameStore` + 首页「继续游戏」） | — | 重启后回到离开时的盘面与计时（已截图验收） |
| 设置持久化 | 玩法开关不再每次重开回到默认 | `SaveCodec` 扩字段 | `strictMode / showNotes / noteMode` 重启后保持 |
| 首页键盘导航 | 桌面纯键盘可用 | 无 | ↑↓ 切换三个入口、Enter 确认，焦点框可见 |
| 计时精度修正 | 长局可信 | 阶段 B 的 `TimeSource` | 与系统秒表误差 < 1 s / 30 min |

### Tier 2 —— 中等投入、构成"完整产品"

| 功能 | 要点 | 依赖 |
|---|---|---|
| 战绩数据 + 统计页（**按墨线风格重设**） | 按难度的最佳 / 平均用时、通关率、最近对局列表；原占位页已随三入口改版移除，需重画 | `GameStore` 扩展 + Repository（阶段 D） |
| 「夜墨」反色主题 | 深底 + 浅墨；作为**显式主题切换**（不做自动跟随系统，见 `docs/02` §9） | `Ink` 增加第二套墨阶，`MiuixTheme` 由参数决定 |
| 每日一题 | 种子 = 日期（`Random(日期哈希)`），可离线、可分享同一盘 | 出题可复现（已具备：随机源注入） |
| 难度模型升级 | 从"空格数"升级为"所需技巧等级"（唯一候选 / 唯一位置 / 区块摒除 / X-Wing） | core 新增技巧求解器；随机种子可复现便于对拍 |
| 提示分级 | 轻提示（指出可填格与理由）→ 中（给候选）→ 重（直接给答案） | 技巧求解器 |
| ~~Monet 取色 / 彩色强调色~~ | **不适用于本风格**（`docs/02` 铁律：禁止色相），改由上面的「夜墨」主题承担主题化需求 | — |
| 逐格无障碍语义 | 屏幕阅读器可逐格朗读 | `semantics` 网格化（把 Canvas 拆成 81 个语义节点或加 `collectionInfo`） |

### Tier 3 —— 探索性（先做技术验证，再谈产品）

| 方向 | 说明 | 主要难点 |
|---|---|---|
| 变体数独 | 6×6 / 12×12 / 锯齿宫 / 对角线 / Killer | 求解器与出题需泛化（当前位掩码写死 9×9） |
| 解释型 AI 提示 | 回答"为什么这格是 7"，给出推理链 | 需要技巧求解器输出步骤，而非仅给出答案 |
| 题目编辑器 / 导入导出 | 标准 81 字符串编码，便于分享与收录 | UI 工作量大（编辑器本身是个独立界面） |
| 联机共同解题 / 对战 | 同一盘面多人协作或竞速 | 需要后端（实时通道 + 房间），与"离线优先"取舍 |
| 音频棋盘 | 视障用户可玩 | 交互范式重构（不只是 a11y 标签） |

## 5. 里程碑与验收标准（DoD）

| 里程碑 | 内容 | 验收标准（可观测） |
|---|---|---|
| **M1 桌面体验收口** | 阶段 B 全部四项 + Tier 1 前两项 | 16+ 项测试全绿；操作 30 分钟无计时漂移；三档窗口肉眼验收通过；相同文案连续提示不再被吞 |
| **M2 Android 落地** | 装 `android-37` + AGP + `androidTarget()` + 图标 + 生命周期暂停 | 模拟器 / 真机安装运行；`enableEdgeToEdge` 下无内容被手势条遮挡；返回键行为正确（菜单→对局→退出） |
| **M3 数据与记录** | `GameStore` 扩展（设置 + 战绩）+ Repository + 统计页（墨线风格重设） | 玩法开关重启后保持；统计页展示真实数据（不造假数据）；清空数据有确认（**对局自动恢复已在 v2.0 达成**） |
| **M4 第二平台** | Web（wasmJs）或 iOS（有 Mac 时） | 新平台冷启动可玩一局；core/state 无改动（diff 为空）；Web 首屏 < 3 s（本机基线） |

## 6. 明确不做（避免范围蔓延）

- 不引入 DI 框架（Koin / Hilt）、导航框架（Navigation）、ORM：当前规模用不上，只会增加跨端适配面。
- 不为"看起来跨平台"而提前拆模块或提前写 `expect/actual`（阶段 C/D 的时机判断见上文）。
- 不引入第二套 UI 组件库（不混用 Material3）：miuix 是唯一视觉来源，否则风格与依赖都会分裂。
- 不做"必须先联网"的核心玩法：数独的完整玩法必须离线可用。
