# 应用图标设计说明（九宫格 · 数字）

> 版本：v1.1（2026-10-06）· 首次发布 + 补齐 §6 Android 自适应图标与 §7 macOS `.icns`
> 关联：`docs/02` 视觉规范（纸墨语言）· `docs/03` §3 打包约定 · `.codebuddy/rules/sudoku-dev.md` 红线 16
> 生成脚本：`tools/make-icon.ps1`（唯一来源，改视觉只需重跑脚本）

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| 一眼看出"这是数独" | 主体是**一个九宫格**，格子里是**数字**——数字是数独唯一无法被误认的特征 |
| **不与五子棋 / 围棋混淆** | 不使用任何"落子"形态：没有实心圆点、没有对角连珠、没有黑白双色对峙、不做对称棋子阵列 |
| 小尺寸仍可读 | **细节随尺寸递减**（数字 5 → 4 → 2 → 1 个），16px 也保住"格子 + 数字"两个要素 |
| 有解题氛围 | 已填数字与空白格**交错分布**；中心格用**中间灰**表示"玩家刚填进去的" |
| 与产品视觉一致 | 只有纸与墨（外加一档中间灰）、圆角纸面、无渐变、无阴影、无色相 |
| 简洁现代 | 几何干净，不做抖动 / 倾斜 / 笔触；数字用无衬线粗体（界面里的手写体在小尺寸下笔形发虚，不适合） |

## 2. 构图与比例（相对画布边长 S）

| 元素 | 比例 | 说明 |
|---|---|---|
| 纸面 | 内缩 `0.055S`，圆角 `0.185S` | 四周透明；深色 / 浅色背景上都不糊边 |
| 纸面描边 | 墨 `#1B1A17` 59% 不透明，宽 ≈ `S/70` | 极细一圈，仅在浅色背景上勾出轮廓 |
| 九宫格 | 内缩 `0.19S`（`< 48px` 时收窄为 `0.15S`） | 小尺寸把网格放大，给数字留落脚处 |
| 宫线 | 外框 `max(1.2, 0.030S)`；内线 `max(0.9, 0.020S)` | 外粗内细，像手画的表格 |
| 数字 | 字号 = `0.62 × 格宽`（16–32px 保底 3px），**且不超过格子的 75%** | 图标里的数字要"顶格"才清楚；上限防止溢出到格线外 |
| 数字落点 | 单元格内**按字形实测尺寸居中**（`MeasureString` + `GenericTypographic`） | 比 `StringFormat` 居中更贴近视觉中心 |

## 3. 数字布局与细节层级

固定布局（保证各尺寸看起来是"同一张图"）：

```
 5 · 3        四角：题目给定 → 实墨 #1B1A17
 · 4 ·        中心：玩家填入 → 中灰 #4B4843 @67%（仅 ≥128px 画）
 9 · 7
```

| 尺寸档 | 画哪些数字 | 理由 |
|---|---|---|
| ≥ 128px | 四角 + 中心（共 5 个） | 细节充足，灰数字表达"解题进行中" |
| 64–127px | 四角（4 个） | 去掉灰数字，避免 5 个数字过密 |
| 32–63px | 左上 `5` + 右下 `7`（2 个） | 留对角两个"锚点"，读作"已填的格子" |
| 16–31px | 左上 `5`（1 个） | 只保"格子 + 一个数字"，避免糊成一团 |

> 数字选型：`5 / 3 / 9 / 7 / 4` 字形互不相似（1 太细、8 易与 0 混、6/9 在极小尺寸易混），四角与中心共 5 个数字**互不重复**，符合数独"同宫不重复"的规则。

## 6. Android 自适应图标（Adaptive Icon）

> 产物：`assets/icon/android/adaptive/res/`（可直接整体拷进 Android 工程的 `res/`）

### 6.1 为什么必须做

Android 8.0 起启动器不再直接使用一张方图，而是拿**前景 + 背景两层**再套上自己的掩膜（Pixel 是圆形、三星是圆角方形、一加是方圆形……），
并且会做轻微视差位移。给单张整图会让每个厂商裁出不同结果（我们旧版"整图 + 四角留边"就是这种情况）。

### 6.2 三个尺寸圈（规范核心）

| 圈 | 尺寸 | 含义 |
|---|---|---|
| 画布 | **108×108dp** | 两层图片的实际尺寸；外圈 18dp 是留给视差位移的余量，**最终不可见** |
| 可见视口 | **72×72dp** | 系统掩膜后实际显示的区域 |
| **安全区** | **直径 66dp 的圆** | **关键内容必须全部落在其中**——掩膜形状与位移都不会裁到它 |

各密度像素：

| 密度 | 缩放 | 画布 108dp | 视口 72dp | 安全圆 66dp |
|---|---|---|---|---|
| mdpi | 1.0× | 108 | 72 | 66 |
| hdpi | 1.5× | 162 | 108 | 99 |
| xhdpi | 2.0× | 216 | 144 | 132 |
| xxhdpi | 3.0× | 324 | 216 | 198 |
| xxxhdpi | 4.0× | 432 | 288 | 264 |

### 6.3 本项目怎么满足安全区（可复算）

九宫格是正方形，最危险的是**四个角**。令九宫格边长 = 0.62 × 可见视口：

```
边长 = 0.62 × 72dp = 44.64dp
对角半径 = 44.64 / 2 × √2 = 31.57dp   ≤   33dp（66dp 的一半）✓
实测（含外框描边与抗锯齿）= 32.0dp     ✓（仍小于 33dp）
```

即：**只按"可见视口"而不是"画布"取比例**，就天然落在安全区内；脚本每次运行都会重新测这个半径并打印 `[OK]/[FAIL]`。

### 6.4 分层设计

| 层 | 内容 | 说明 |
|---|---|---|
| `ic_launcher_background.png` + `@color/ic_launcher_background` | 平铺纸色 `#F7F5F0` | **full-bleed**：铺满 108dp，不画边距也不描边（形状由掩膜决定，描边会变成一圈脏边）；同时给出颜色资源，工程里可只用颜色、不打包背景图 |
| `ic_launcher_foreground.png` | 九宫格 + 数字（透明底） | 按可见视口 62% 绘制；灰数字（"玩家填入"）在 ≥128px 档存在 |
| `ic_launcher_monochrome.png` | 同一构图的**单色剪影** | Android 13+ 主题图标：系统统一着色，所以**不允许**灰度差异，中心数字也用实墨 |

三层都按 5 个密度输出，尺寸即上表 108dp 那一列（108/162/216/324/432）。

### 6.5 资源结构与 XML（脚本已生成，可直接用）

```
assets/icon/android/adaptive/res/
├── mipmap-mdpi/    ic_launcher_foreground.png  ic_launcher_background.png  ic_launcher_monochrome.png
├── mipmap-hdpi/    （同上）        ├── mipmap-xhdpi/   （同上）
├── mipmap-xxhdpi/  （同上）        └── mipmap-xxxhdpi/ （同上）
├── mipmap-anydpi-v26/ic_launcher.xml、ic_launcher_round.xml
└── values/ic_launcher_background.xml
```

`mipmap-anydpi-v26/ic_launcher.xml`（`ic_launcher_round.xml` 内容相同）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@color/ic_launcher_background" />
    <foreground android:drawable="@mipmap/ic_launcher_foreground" />
    <monochrome android:drawable="@mipmap/ic_launcher_monochrome" />
</adaptive-icon>
```

`values/ic_launcher_background.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <color name="ic_launcher_background">#F7F5F0</color>
</resources>
```

### 6.6 接入步骤（M2 Android 落地时执行）

1. 建 `composeApp/src/androidMain/res/`，把 `adaptive/res/` 下的 `mipmap-*` 与 `values/` **整体拷入**；
2. 把 §5.2 的传统 `ic_launcher.png` / `ic_launcher_round.png`（48–192）也拷进对应的 `mipmap-*`（给 8.0 以下兜底）；
3. `AndroidManifest.xml` 里 `android:icon="@mipmap/ic_launcher"`、`android:roundIcon="@mipmap/ic_launcher_round"`；
4. 顺带把 `play-store-512.png` 作为商店素材上传（Google Play 要求 512×512 且带 alpha 的 PNG）。

## 7. macOS `.icns`

### 7.1 两条路径

| 路径 | 需要 | 适用 |
|---|---|---|
| **A. 本仓库脚本直接产出**（已实现） | 无（Windows 上即可） | 日常出包：脚本按 Apple 规范写出 11 个 PNG 块，`macos { iconFile }` 直接可用 |
| **B. macOS 官方 `iconutil`** | macOS（自带 `iconutil` / `sips`） | 需要 Apple 官方工具背书的发布流程；脚本已把 `.iconset` 备好，一条命令即可 |

### 7.2 图像规格要求

- 格式：PNG、带 alpha、sRGB、**不预乘**、非交错（脚本用 System.Drawing 输出，满足）；
- `.iconset` 目录的 10 个文件必须**严格按命名**（`iconutil` 按名识别）：

| 文件名 | 像素 | 用途 |
|---|---|---|
| `icon_16x16.png` | 16 | Finder 列表 / 16pt@1x |
| `icon_16x16@2x.png` | 32 | 16pt@2x |
| `icon_32x32.png` | 32 | 菜单栏 / 32pt@1x |
| `icon_32x32@2x.png` | 64 | 32pt@2x |
| `icon_128x128.png` | 128 | Dock 最小 / 128pt@1x |
| `icon_128x128@2x.png` | 256 | 128pt@2x |
| `icon_256x256.png` | 256 | 256pt@1x |
| `icon_256x256@2x.png` | 512 | 256pt@2x |
| `icon_512x512.png` | 512 | 512pt@1x |
| `icon_512x512@2x.png` | 1024 | **App Store / Retina Dock** |

### 7.3 `.icns` 内部结构（脚本按此写入）

```
'icns' + 文件总长(大端 4B) + 块×11
每块 = 类型(4B ASCII) + 块长(4B 大端，含 8B 头) + PNG 数据
```

| 块类型 | 像素 | 对应 pt | 块类型 | 像素 | 对应 pt |
|---|---|---|---|---|---|
| `icp4` | 16 | 16@1x | `ic10` | 1024 | 512@2x |
| `icp5` | 32 | 32@1x | `ic11` | 32 | 16@2x |
| `icp6` | 64 | 32@2x | `ic12` | 64 | 32@2x |
| `ic07` | 128 | 128@1x | `ic13` | 256 | 128@2x |
| `ic08` | 256 | 256@1x | `ic14` | 512 | 256@2x |
| `ic09` | 512 | 512@1x | | | |

（`icp5`/`ic11`、`icp6`/`ic12`、`ic08`/`ic13`、`ic09`/`ic14` 像素相同但语义不同——Apple 自己的输出也同时包含，属正常。）

### 7.4 转换流程

**路径 A（本仓库，Windows 上直接出）**

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-icon.ps1
# 产出：assets/icon/macos/SudokuInk.icns（交付 + 复核）与 composeApp/icons/SudokuInk.icns（打包用，jpackage macos.iconFile）
```

**路径 B（macOS 上用官方工具复核 / 重建）**

```bash
# 1) 把 assets/icon/macos/SudokuInk.iconset 拷到 macOS
# 2) 生成 icns（--convert icns --output 也可写作 -c icns）
iconutil -c icns SudokuInk.iconset -o SudokuInk.icns
# 3) 反向验证：把 icns 解回 iconset，逐档检查尺寸
iconutil -c iconset SudokuInk.icns -o check.iconset && ls -l check.iconset
# 4) 若需从单张 1024 重建整套（可选）
sips -z 512 512 source/sudoku-1024.png --out icon_512x512.png
```

### 7.5 接入与验收

- 接入：`composeApp/build.gradle.kts` → `nativeDistributions.macos { iconFile.set(project.file("icons/SudokuInk.icns")) }`（**已接入**）；
  另注：`.ico` / `.icns` 已从 jar 资源里排除（只供 jpackage 读取，不必进 jar）。
- 本仓库可做的验收（结构层）：脚本 + 复核脚本逐块解析 → `magic=icns`、头部声明长度 = 文件长度、11 块全为 PNG 且像素与上表一致、无空隙（实测 **98 KB / 11 块 / 0 异常**）。
- 只能在 macOS 上做的验收（渲染层）：`iconutil -c iconset` 反解、Finder / Dock 实际观感、DMG 安装后图标。
- 注意：Windows 的 `System.Drawing.Icon` **不能**读 `.icns`（它只认 ICO），这是正常的，不是文件损坏。

## 8. 复现与验收

```powershell
# 生成全部产物（运行时 / 打包 + 各平台交付 + 两张校验图）
powershell -ExecutionPolicy Bypass -File tools\make-icon.ps1
# 改完图标必须重新打包，否则 exe 里还是旧图标
.\gradlew.bat :composeApp:createDistributable
```

验收要点：

1. 看 `assets/icon/preview.png`：256px 应能读出 `5 / 3 / 4 / 9 / 7`；32px 能读出至少两个数字；16px 是"格子 + 一块墨"。
2. 看 `assets/icon/android/adaptive/preview.png`：九宫格完整落在 66dp 安全圆内；四种掩膜下不裁字、不裁格线。
3. 脚本输出应为：`前景最大半径 32.0dp / 安全区 33.0dp [OK]`、`.icns 11 块`。
4. 启动打包后的 `SudokuInk.exe`：**标题栏与任务栏**都应是新图标（这两处由运行时代码设置，与 exe 文件图标是两条独立路径，见 `docs/03` §3）。
5. 资源管理器里的 `SudokuInk.exe` 文件图标若仍显示旧图，多为 Windows 图标缓存，刷新即可。

  介意的话走 §7.1 路径 B，用 `iconutil` 从 `.iconset` 重建。
