# 应用图标设计说明（九宫格 · 数字）

> 版本：v1.0（2026-10-06）· 首次发布
> 关联：`docs/02` 视觉规范（纸墨语言）· `docs/03` §3 打包约定 · `.codebuddy/rules/sudoku-dev.md` 红线 16
> 生成脚本：`tools/make-icon.ps1`（唯一来源，改视觉只需重跑脚本）

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| 一眼看出"这是数独" | 主体是**一个九宫格**，格子里是**数字**——数字是数独唯一无法被误认的特征 |
| **不与五子棋 / 围棋混淆** | 不使用任何"落子"形态：没有实心圆点、没有对角连珠、没有黑白双色对峙、不做对称棋子阵列 |
| 小尺寸仍可读 | **细节随尺寸递减**（数字 5 → 4 → 2 → 1 个），16px 也保住"格子 + 数字"两个要素 |
| 有解题氛围 | 已填数字与空白格**交错分布**；中心格用**中间灰**表示"玩家刚填进去的" |
| 与产品视觉一致 | 只有纸与墨（外加一档中间灰）、圆角纸面、无渐变、无阴影、无色相 |
| 简洁现代 | 几何干净，不做抖动 / 倾斜 / 笔触；数字用无衬线粗体（界面里的手写体在小尺寸下笔形发虚，不适合） |

## 2. 构图与比例（相对画布边长 S）

| 元素 | 比例 | 说明 |
|---|---|---|
| 纸面 | 内缩 `0.055S`，圆角 `0.185S` | 四周透明；深色 / 浅色背景上都不糊边 |
| 纸面描边 | 墨 `#1B1A17` 59% 不透明，宽 ≈ `S/70` | 极细一圈，仅在浅色背景上勾出轮廓 |
| 九宫格 | 内缩 `0.19S`（`< 48px` 时收窄为 `0.15S`） | 小尺寸把网格放大，给数字留落脚处 |
| 宫线 | 外框 `max(1.2, 0.030S)`；内线 `max(0.9, 0.020S)` | 外粗内细，像手画的表格 |
| 数字 | 字号 = `0.62 × 格宽`（16–32px 保底 3px），**且不超过格子的 75%** | 图标里的数字要"顶格"才清楚；上限防止溢出到格线外 |
| 数字落点 | 单元格内**按字形实测尺寸居中**（`MeasureString` + `GenericTypographic`） | 比 `StringFormat` 居中更贴近视觉中心 |

## 3. 数字布局与细节层级

固定布局（保证各尺寸看起来是"同一张图"）：

```
 5 · 3        四角：题目给定 → 实墨 #1B1A17
 · 4 ·        中心：玩家填入 → 中灰 #4B4843 @67%（仅 ≥128px 画）
 9 · 7
```

| 尺寸档 | 画哪些数字 | 理由 |
|---|---|---|
| ≥ 128px | 四角 + 中心（共 5 个） | 细节充足，灰数字表达"解题进行中" |
| 64–127px | 四角（4 个） | 去掉灰数字，避免 5 个数字过密 |
| 32–63px | 左上 `5` + 右下 `7`（2 个） | 留对角两个"锚点"，读作"已填的格子" |
| 16–31px | 左上 `5`（1 个） | 只保"格子 + 一个数字"，避免糊成一团 |

> 数字选型：`5 / 3 / 9 / 7 / 4` 字形互不相似（1 太细、8 易与 0 混、6/9 在极小尺寸易混），四角与中心共 5 个数字**互不重复**，符合数独"同宫不重复"的规则。

## 6. 复现与验收

```powershell
# 生成全部产物（运行时 + 交付 + 校验图）
powershell -ExecutionPolicy Bypass -File tools\make-icon.ps1
# 改完图标必须重新打包，否则 exe 里还是旧图标
.\gradlew.bat :composeApp:createDistributable
```

验收要点：

1. 看 `assets/icon/preview.png`：256px 应能读出 `5 / 3 / 4 / 9 / 7`；32px 能读出至少两个数字；16px 是"格子 + 一块墨"。
2. 启动打包后的 `SudokuInk.exe`：**标题栏与任务栏**都应是新图标（这两处由运行时代码设置，与 exe 文件图标是两条独立路径，见 `docs/03` §3）。
3. 资源管理器里的 `SudokuInk.exe` 文件图标若仍显示旧图，多为 Windows 图标缓存，刷新即可。

## 7. 已知限制

- **macOS `.icns`**：`iconutil` 仅 macOS 提供，本脚本不生成；打包 DMG 前需在 macOS 上用 `source/sudoku-1024.png` 生成 `sudoku.icns`。
- **iOS `Contents.json`**：只给了 PNG 规格，未生成 Xcode 资源目录清单（接入 iOS 工程时按 §5.2 的尺寸建 Asset Catalog）。
- **自适应图标（Android Adaptive / iOS 单色）**：未做前景 / 背景分层版本；当前是单一整图，圆形遮罩下四角会被裁掉少量背景（内容仍在安全区内）。
