## 1. 评审方法：把四个奖项的评选口径收敛成可打分的五维

四个奖各有侧重，但反复出现的共同口径只有五条，因此本项目直接按这五维自评、并逐条给证据：

| 奖项 | 官方口径里的关键词 | 收敛到本项目的评审项 |
|---|---|---|
| CA 国际设计奖 | 概念（concept）、工艺（craft）、视觉传达 | **美学与工艺**：线条、排版、比例是否经得起放大看 |
| 德国设计奖 | 整体概念、功能、美学、创新、可持续、社会责任 | **创新性** + **可持续性** + **功能性** |
| IDEA | 创新、用户价值、美学、细节、设计策略 | **用户体验** + **美学与工艺** |
| 红点奖 | 形式质量、功能、情感内容、耐久 | **美学与工艺** + **用户体验** + **可持续性** |

评分 5 分制，4.0 = "可以送审的水平"，4.5+ = "有机会入围"。**这是自评，不是获奖承诺**。

## 2. 整改前的现状盘点（全部有据）

用脚本把全站视觉常量扫了一遍（色板 / 线宽 / 圆角 / 字号 / 间距 / 透明度 / 动效），结论如下。

| 维度 | 整改前 | 关键证据 |
|---|---|---|
| 创新性 | **4.5** | 「手写纸 · 简约油墨」是完整自洽的概念：抖动由 `wobble(seed)` 纯函数生成（同一根线每次重绘完全一致，**不会闪**——这是"手绘感"落地最难的一环，见 `Ink.kt:88`）；**全站无彩色**，编辑状态靠线重 + 墨的浓淡表达（冲突格用排线而非标红） |
| 功能性 | **4.5** | 唯一解校验、笔记、候选、提示、撤销重做、存档 v1→v2 兼容、键盘全链路、悬浮输入面板（只列该格可填） |
| 美学与工艺 | **3.0** | 字号散落 **13 档**（10/11/12/13/14/15/16/17/18/21/22/28/40）且**无令牌、无行高、几乎无字重**；`lineHeight` 全站 0 处；"纸"有 **3 个来源**（`Ink.Paper` / `Ink.PaperShade` / `Color.White`）；存在**死令牌** `Ink.StrokeWidth`（4 个值与 `DesignTokens.Stroke` 全部冲突且零引用）；魔法尺寸 3 / 7 / 18 / 46 dp；分隔线硬编码 `1.2.dp`（重复了 `Stroke.Thin` 的值，改令牌不会同步） |
| 用户体验 | **3.5** | 键盘优先 ✓、悬浮键只列可填 ✓；但**"当前项"高亮几乎不可见**（底纹 `Wash×0.55 ≈ 0.039`，比悬停还淡）——键盘用户在抽屉里看不出焦点在哪一项；最淡一级墨 `#8B867C` 对纸面只有 **3.32:1**（小字不达 WCAG AA 4.5:1） |
| 可持续性 | **3.5** | 自绘控件不随第三方 UI 套件改版而失效 ✓；图标 / 资产一键再生 ✓；但设计令牌没有文档化的"唯一出口"约定，靠人记 ✗ |

## 4. 优化路线（P1 / P2，含验收标准）

### P1 — 直接影响评审结果

> 进度：**P1 四项全部完成**。#1 格子级语义、#2 减少动态效果 已于第七轮完成（`docs/05` §5.6）；#3 打包手写体已于第八轮完成（§5.7，正文霞鹜文楷 + 数字 Nunito，OFL）；
> #4 落笔成局已于第九轮完成可行性评估、**第十轮实施落地**（§5.9）——评估与实施记录见本节末。

| # | 项 | 为什么会影响评奖 | 验收标准 |
|---|---|---|---|
| 1 | **格子级无障碍语义** | IDEA 的 "Benefit to user"、德国设计奖的 "社会责任" 都是硬指标。当前棋盘是**整盘一个语义节点**，屏幕阅读器无法按格朗读"第 4 行第 7 列 = 空 / 候选 2、9" | Compose UI 测试断言语义树存在 81 个格子节点，且给定格与空格朗读文案不同（**已转正**，见 `docs/02` §7） |
| 2 | **尊重"减少动态效果"** | 系统级 reduced-motion 是当代无障碍与"社会责任"的常见扣分点；本项目动画虽少（3 处）但未响应系统开关 | 打开系统 reduced-motion 后，抽屉改为瞬时出现（时长 0），其余不变；用 UI 测试断言动画时长被替换 |
| 3 | **打包手写体** | 当前依赖系统楷书，取不到就回退衬线体 → **跨平台字形不一致**，这是"工艺一致性"的硬伤（评审会看同一设计在不同环境的呈现） | 打包一份开源可商用中文手写体（如霞鹜文楷 / 站酷系列），三平台字形完全一致；字体文件随 jar 分发，`docs/03` 记录许可与体积 |
| 4 | **落笔成局（棋盘初次呈现）** ✅ **第十轮完成** | 红点看"情感内容"：本作此前只有静态棋盘，缺一处**让人记住的瞬间**。开局时棋盘以 120–160ms 的"墨迹由淡到浓"整体显影，且不阻塞计时 | 动效 ≤ 200ms、可被 reduced-motion 关闭；不影响首帧可交互（按键立刻可用）；冒烟截图留档 |

#### P1-4「落笔成局」可行性评估（2026-10-07，第九轮）

| 维度 | 结论 | 依据 |
|---|---|---|
| 技术可行性 | **高** | `BoardCanvas` 是 `Canvas` 自绘，只要在绘制出口统一乘一个 `revealProgress`（0→1）即可；用 `animateFloatAsState` + `tween(motionDurationMs(180))` 驱动，令牌与注入点都已就绪 |
| "不阻塞首帧交互" | **可满足** | 显影只作用于绘制层的 alpha，不 gate 输入：动画期间点击与键盘照常响应 |
| 可被 reduced-motion 关闭 | **可满足** | 时长过 `motionDurationMs()`，开启时返回 **0** → 瞬间就位（是"归零"而不是"变淡"） |
| 可测性 | 中 | UI 测试用 `mainClock.advanceTimeBy` 断言；"进度 → alpha"宜抽成纯函数做单测 |
| 成本 | **低（≤ 0.5 人天）** | 1 个参数 + 3–5 处绘制调用 + 1–2 个测试 |
| 主要风险 | ① **不要**把 alpha 混进文本缓存键（命中率会崩），只做整体后乘；② 必须时长归 0，不是"变淡" | `BoardCanvas` 的文本缓存键目前是"数字 + 颜色 + 字号 + 字重" |
| 评奖收益 | 锦上添花 | 对应红点"情感内容"维度；但**不是门槛项**（#1 #2 才是门槛） |

**结论与决定**：技术上完全可行、成本低、风险可控。第九轮的交付范围只有字体与依赖清理，故当时决定暂缓；
此前 `fce2aa9` 的实现与配套测试已被移除（见 `docs/05` §5.8）。**第十轮按本表实施**，记录如下。

#### P1-4「落笔成局」实施记录（2026-10-07，第十轮）

| 项 | 落点 |
|---|---|
| 时长令牌 | `DesignTokens.Motion.RevealMs = 160`（动效第四档）。≤ 200ms 是验收线、≥ 120ms 才看得见"由淡到浓"，`MotionPolicyTest` 断言 `in 120..200` |
| 触发时机 | `BoardCanvas` 内 `rememberBoardReveal(game.puzzle)`：key 取 **`game.puzzle` 的引用**——一局之内 reducer 只做 `game.copy(current = ...)`，puzzle 实例始终不变；只有**开新局 / 载入存档**才换新实例（`Game(...)` 全仓仅这两处构造，已核对）。从菜单再进对局 = 棋盘重新出现，也重播一次 |
| 显影方式 | `Modifier.graphicsLayer { alpha = reveal }`——**整盘淡入**，而非逐笔乘 alpha。理由：整个棋盘在一个 `Canvas` 里绘制，逐个绘制调用乘系数要改 12+ 处；整盘淡入在视觉上同样读作"墨迹由淡到浓"（棋盘纸 `PaperSheet` 与页面纸 `Paper` 的色差极淡），且**完全不触碰文本缓存键**——正是上表列的头号风险 |
| reduced-motion | 开启时**初始即"已显影"**（不是靠"0 时长补一帧"），因此不会出现"先空一帧再出现"的闪烁 |
| 不阻塞交互 | 只作用于绘制层 alpha，`pointerInput` 与键盘照常；`BoardCanvasUiTest.revealDoesNotSwallowFirstClicks` **故意不推进测试时钟**（此时 alpha 仍为 0、棋盘"看不见"）就点击，专门守这条 |

**验收对照**：动效 ≤ 200ms ✓（160ms，`MotionPolicyTest`）；可被 reduced-motion 关闭 ✓（时长归 0，且初始已显影）；
不影响首帧可交互 ✓（专项 UI 测试）；冒烟截图留档 ✓（`smoke_5_board_one_empty.png`：显影已走完、棋盘完整不透明）。

### 已知取舍（不打算改，写清理由）

- **候选数字不做 AA 对比度**：它是有意为之的次级冗余通道——同一信息在悬浮面板（只列可填）与数字键盘的重墨强调里都能拿到，做得太黑会与"题目给定"的数字抢层级。浓度从 0.42 提到 0.50 已是可读性与层级感的平衡点；
- **不用字重做层级**：系统手写体没有真 Bold，Compose 合成粗体会发虚，破坏手绘工艺感。层级只靠"字号 + 字距 + 墨的浓淡"；
- **不做阴影 / 渐变 / 彩色状态**：与"只有纸与墨"直接冲突。

## 6. 结论

- **概念与工艺**已经是可送审水准（创新性 4.5 / 功能性 4.5）：手绘墨线的确定性抖动、无彩色的状态表达、"纸与墨"三层纸+四级墨的体系，都是能被评审记住的点；
- **短板集中在"系统化"而非"审美"**：字号无阶梯、"纸"多来源、死令牌、魔法尺寸、高亮不可辨、最淡墨不达 AA——本轮已全部整改并留证；
- 若要真去冲奖，**P1 的四项是门槛项**：格子级无障碍、reduced-motion、打包字体（跨平台字形一致）、一处可被记住的动效瞬间。前两项不做，功能与无障碍维度的失分会直接盖过美学加分。
