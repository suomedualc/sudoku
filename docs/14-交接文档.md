## 1. 十分钟上手

### 1.1 这是什么

Kotlin Multiplatform + Compose Multiplatform 的**数独游戏**，视觉是"手写纸 + 简约油墨"（纸墨 / 夜墨两套主题）。
**无第三方 UI 组件库**——所有控件、图标、棋盘都是 `Canvas` 自绘。

当前启用 **Android + Desktop(JVM)** 两个目标。iOS / Web 未启用但"接入即用"（见 §2.6）。

### 1.2 三条命令

```powershell
cd X:\sudoku-main

# ① 跑测试（唯一能自动验证行为的入口，务必先跑一遍确认基线）
.\gradlew.bat :composeApp:jvmTest --offline           # 161 项（commonTest 126 + jvmTest 35）
.\gradlew.bat :composeApp:testDebugUnitTest --offline # 133 项（= 同一批 commonTest 126 重复跑 + Android 独有 7）

# ② 桌面端跑起来看效果
.\gradlew.bat :composeApp:run --offline

# ③ 编译双端（改动 commonMain 后两个都要过）
.\gradlew.bat :composeApp:compileKotlinJvm :composeApp:compileDebugKotlinAndroid --offline
```

**当前基线：去重 168 项测试全绿**（`jvmTest` 161 = commonTest 126 + jvmTest 35；`testDebugUnitTest` 133 = 同一批 126 重复 + Android 独有 7）。
两条命令**重复跑**了 commonTest，所以**不要把 161 + 133 相加**——真实用例数是 **168**。

## 2. 架构：只需记住这 4 件事

### 2.1 三层单向依赖（这是全项目最重要的不变量）

```
core/     纯算法：Sudoku（位掩码 + MRV 回溯出题/求解）· CellCursor（光标策略）
            ↑ 零平台依赖、零 UI、零 IO
state/    纯状态机：GameAction → GameReducer.reduce() → Reduction(state, Msg)
           GameState（不可变快照）· GameStore/SaveCodec（存档）· GameViewModel（唯一桥）
            ↑ 零平台依赖（存档走"端口注入"而非 expect/actual）
ui/       声明式 UI：theme（墨线令牌）· components（全自绘）· screens · i18n
            ↑ 仅通过 6 个 expect/actual 触达平台
platform/ androidMain / jvmMain：GameStore 实现 · 字体 · 安全区 · 返回键 · 语言
```

**红线**：`core/` 和 `state/` **不许**出现 `android.*`、`java.io`、`androidx.*`。改这两层必须能在 `commonTest` 里跑。

### 2.2 状态机的形状

```kotlin
data class Reduction(val state: GameState, val message: Msg? = null)
GameReducer.reduce(state, action, random): Reduction
```

**关键设计：提示是"事件"不是"状态"**。
`message` 作为 `Reduction` 的第二返回值 + `GameViewModel` 的 `Channel` 投递——
如果放回 `GameState` 里，**相同文案会被 data class 等值比较吞掉**（这是修过的真实缺陷，见 `docs/05` §1 已知缺口 1）。

**`Msg` 是语义键不是文案**：`Msg.Conflict(value)` / `Msg.Win(elapsed, usedHints)`，
渲染在 `ui/i18n/Strings.render(msg)`。单测断言语义，不断言文案。

### 2.3 `GameAction` 全集（23 个，改动前先看这里）

| 类别 | Action |
|---|---|
| 对局 | `NewGame` · `Reset` · `Reveal` · `Hint` · `Pause` · `Resume` |
| 输入 | `Digit(value, advance)` · `NoteDigit(value)` · `Select` · `Deselect` · `Move` · `FocusFirstEmpty` |
| 历史 | `Undo` · `Redo` |
| 偏好 | `ToggleNoteMode` · `ToggleStrict` · `ToggleShowNotes` · `ToggleHintCandidates` · `ToggleDarkMode` · `SetLanguage` |
| 其它 | `BindKey` · `SyncElapsed` · `Navigate` |

**`Digit` vs `NoteDigit` 的区别很重要**（2026-10-24 新增）：
- `Digit` 行为取决于全局 `noteMode` 开关；
- `NoteDigit` **无视 `noteMode`**，直接记笔记——这是双键盘（点空心数字）要的语义。
- reducer 内部走同一个 `place()`，靠 `forceNote` 参数区分。

## 3. 关键机制（改动前必读）

### 3.1 存档

**位置**：桌面 `~/.sudoku-ink/save.txt` · Android `filesDir/save.txt`

**格式 v2**：纯文本 `key=value`，无第三方序列化依赖（所以能在 `commonTest` 直接测）。

```
v=2
strict=0 / showNotes=1 / noteMode=0 / hintCandidates=0 / darkMode=1
keyMap=... / language=ZhCn / stats=...
game=1                      ← 有对局时才有以下块
difficulty=Easy / puzzle=<81位> / current=<81位> / solution=<81位>
notes=<81个逗号分隔整数> / elapsed=123 / hintUsed=0 / hintsCount=0
```

**兼容策略**：逐字段宽松降级——坏难度→Normal、缺行→默认、整体失败→返回 `null` 而非抛异常。
**存档是外部输入，一个坏字段不该废掉整局。**

**写盘**：`tmp + ATOMIC_MOVE` 原子写，同目录保证 move 原子性。

### 3.2 多实例写锁（**极易踩**）

`MutexGameStore(base, FileSaveMutex(saveFile))` —— 抢不到写锁则**降级只读**，由 `App` 弹一次墨条告知。

> ⚠️ **文件锁在同一 JVM 内是共享的**：第二个 `tryLock()` **不等待**，直接抛
> `OverlappingFileLockException`。所以只要"抢锁"发生两次，第二次必然失败。

**因此 Android 端必须用进程级单例**（`MainActivity.companion.sharedStore()`）。
曾经把它建在 `remember`（Activity 作用域），**旋转一次就静默变只读，本局所有进度不再落盘**（P1-A，见 `docs/13` §7.1）。

**新平台/新入口接 `MutexGameStore` 时，先问自己：这个作用域会被重建吗？**

### 3.3 计时

单调时钟 + 锚点并账，**不是"每秒 +1"**。长局不漂移；切后台/最小化精确停表。
`SyncElapsed(seconds)` 是心跳动作，**绝不能因此触发重算**（见 §3.4）。

### 3.4 性能约定

- `derivedStateOf` 缓存 conflicts / progress —— 心跳 250ms **不能**触发 81 格重算；
- `NumberPad` 的 `legalMask` / `remaining` 用 `remember` 缓存，key 是 `game` / `selected`；
- **出题实测 <20ms**（Expert 最慢 17ms），所以 `dispatch` 同步执行是安全的。
  若将来引入网络题库/动画出题，才需要考虑异步。

### 3.5 布局断点（2026-10-24 刚统一，别再改乱）

```kotlin
gameLayout(width, height) = if (width > height && height < 480.dp) Landscape else Portrait
```

**高度上限 480dp 是关键**：只看"宽>高"时，桌面默认窗口 1180×900 会被判成横屏，
双栏会把棋盘压窄、1–9 横排挤成九宫格——与 `docs/02` §7「只有一条纵列」相悖。

**横屏不留上下浮动条槽**：撤销/重做改挂棋盘左侧竖轨（`BarRail`），用横向富余换纵向。
实测 891×411dp 棋盘由 160dp（单格 17dp，撞 `BoardMinSize` 下限）提升到 237dp（27dp）。

### 3.6 双键盘（B1，2026-10-24 新增）

主键盘下方一排**空心数字**，点它直接记笔记。**按纵向预算决定是否显示**：

| 方案 | 纵向 | 结论 |
|---|---|---|
| 3×3 同构 | 128dp | ✗ 360×640 把「游戏设置」挤出屏幕 |
| 单行+右侧留白 | 40dp | ✗ 每键 27dp，空心数字糊成竖线 |
| **单行、不留白** | **40dp** | ✓ 三种尺寸都放得下 |

`showNotePad` 由 `GameScreen` 按预算算，`NumberPad` 只认这个布尔值。
**极小屏（360×640）自动隐藏**，退回"先切笔记模式"的老路。

## 4. 视觉与文案纪律

### 4.1 两条铁律

1. **不靠颜色区分状态**——夜墨主题下颜色翻转，字形/线型不翻。
   用：线重（重墨/中墨/淡墨）、线型（实线/虚线）、字形（实心/空心）。
2. **只有纸墨两色 + 墨四级 alpha**——`Ink.Black` / `Grey` / `Light` / `Faint`。
   对比度实测值写在 `Ink.kt` 注释里（如 17.40:1）。

### 4.2 所有可见文字必须走 `Strings`

`Strings` 是接口，`ZhStrings` / `EnStrings` 各实现一遍。
**`I18nGuardTest` 用 JDK 反射反推接口 getter**，逐键断言两种语言非空白、占位符一致。
新增文案 → 两个实现都要加，否则测试红。

**但守卫查不出"声明了没人用"**——加 key 后要自己 grep 确认有引用。

### 4.3 触控目标 ≥48dp

`HitAreaTest` 守着数字键 / 悬浮面板键 / 紧凑条目 / 图标按钮。
棋盘格是网格单元格，不套用按钮标准（测试里已注明）。

### 5.3 实机冒烟（`tools/smoke-e2e.ps1`）

```powershell
.\gradlew.bat :composeApp:createDistributable --offline
powershell -NoProfile -ExecutionPolicy Bypass -File tools\smoke-e2e.ps1 -Flow all
```

11 条流：`menu` / `exit` / `win` / `theme` / `bar` / `ux` / `keys` / `keymap` / `stats` / `lang` / `reveal`。
脚本会**备份并恢复玩家存档**，截图落在 `%TEMP%`。

> ⚠️ **DPI 前提（2026-10-24 修过）**：脚本内置 `Set-DpiAware()`（PER_MONITOR_AWARE_V2）+ 按 `Get-DpiScale` 换算。
> 漏掉它会怎样：PowerShell 默认 DPI 不感知，`GetWindowRect` 给虚拟坐标而
> `SetCursorPos`/`CopyFromScreen` 用物理坐标 → **表现为"顶栏图标消失、棋盘溢出"，极像 UI bug**。
> **换机器跑冒烟前，先排除"是 DPI 不是 UI"。**

> ⚠️ **三个已确认但未修的脚本缺陷（2026-10-24 第二轮实测，均属工具链不是产品）**：
>
> | # | 现象 | 根因 | 规避 |
> |---|---|---|---|
> | 1 | 截图里棋盘是**空白**（`smoke_3_game_hard` 首跑） | `Save-Shot` 无重绘同步，截在显影动画首帧（`DesignTokens.Motion.RevealMs = 160`ms） | 复跑即可；或截图前加 ≥250ms 等待 |
> | 2 | `-Flow all` 连跑时 `FOREGROUND LOST` 中止 / 窗口尺寸残留（1244×… 而非 1770×1350） | `Pin()` 用 `SetWindowPos(HWND_TOPMOST)` 抢前台，被系统交接给别的窗口 | **每条流单独起一个进程**，流间 `Start-Sleep` |
> | 3 | `bar` 流首个按键可能被当成"打开难度抽屉" | 同上，`Pin` 在 `Down`/`Enter` 之间打断键盘焦点 | 单跑该流；断言看截图而非退出码 |
>
> **判据**：DPI 150% 下 `Pin` 后窗口应为 **1770×1350**；截图尺寸若为 237×39 之类，是抓到残窗，**不可据此报 UI 缺陷**。

## 7. 坑（按踩坑成本排序）

### 7.1 会静默损坏数据的

1. **Android 存档必须进程级单例** —— 建在 `remember` 会在旋转后静默只读（§3.2）。
2. **存档是外部输入** —— `load()` 坏数据必须返回 `null`，不能抛异常（启动期抛 = 起不来）。
3. **`outcomeCounted` 不随 Snapshot 回滚** —— `reset()` 必须显式清它，否则"通关→重置→再赢"第二次不计胜场。

### 7.2 会让功能"看起来做了其实没有"的

4. **`GameAction.Reveal` 曾整条链路不可达** —— reducer/文案/测试全写好了，UI 里没有按钮派发。
   **加新 Action 后必须 grep 确认有 UI 派发点。**
5. **声明了但没人用的 i18n key** —— `I18nGuardTest` 查不出这类，要自己 grep。
6. **布局预算** —— 加一行控件前先算纵向/横向够不够。B1 改了三版才定下来（§3.6）。

### 7.3 环境类

7. **JDK 25 会让 Gradle 8.14.4 直接失败**，报错只有版本号一串。
8. **冒烟脚本的 DPI** —— 见 §5.3 告警，症状酷似 UI bug。
9. **首次构建需联网** —— Kotlin 插件按 Gradle 版本分发不同变体 jar（`-gradle813`），
   本地缓存只有旧版那份；拉过一次后 `--offline` 正常。

## 10. 一句话总结

> 三层单向依赖、`core`/`state` 零平台依赖、提示走事件不走状态、
> 不靠颜色靠字形与线重、改完必须跑全量测试（jvmTest 161 + Android 7，去重 168）、
> 修缺陷必须配能反向验证的回归测试、
> **Android 的存档实例绝不能建在会被重建的作用域里**。
>
> 第二轮补充的两条元经验：
> **规则要放在 agent 能自动加载的位置**（`.codebuddy/` 写了也等于没写，`AGENTS.md` 才算数）；
> **结论要能反向证伪**——`Test-Path` 证不了大小写、`UP-TO-DATE` 等于没跑、截图不等于 UI 正确（见 `AGENTS.md` §12）。
